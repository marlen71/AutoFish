# Discord: внешний наблюдатель Eternal Core

Наблюдатель необязателен и запускается **на другом постоянно работающем устройстве или VPS**, не на серверном ПК. Иначе он не сможет сообщить Offline при выключении этого ПК. Нужны Python 3.9+, доступ по HTTPS к серверу Eternal Core, GitHub и Discord; дополнительные пакеты не нужны. Если отключится сам наблюдатель или его сеть, статус в Discord может устареть. Online/Offline означает доступность сервера **с точки зрения наблюдателя**, а не гарантированную доступность со всего интернета.

## Перед настройкой

1. В Discord отзовите и замените любые ранее раскрытые webhook. Ссылка webhook — секрет с правом публиковать сообщения. **Не присылайте её в чат, не кладите в Git, клиентские архивы, журнал или скриншоты.** Два webhook должны быть разными: первый указывает на канал статуса, второй — на канал кратких обновлений. Канал определяется самим webhook; ID канала или категории в настройках не требуется.
2. Сохраните резервную копию `data`, остановите сервер, обновите `server.py`, `internet_gateway.py` и папку `static` из новой серверной сборки, не заменяя `data`. При первом запуске существующая SQLite-база мигрируется; для ранее созданных продуктов установлен консервативный `OUTDATED`. В панели администратора откройте «Игры и макросы → Настройка макроса», назначьте каждому продукту `UPDATED`, `ON UPDATE`, `AT YOUR OWN RISK` или `OUTDATED` и сохраните. Это ручной публичный статус, он **не** включает и не отключает подписку.
3. Публичный HTTPS-шлюз отдаёт только каталог с названиями продуктов и их статусами по `/api/status`; логины, UID, подписки, токены и ключи там не публикуются. Учитывайте, что каталог будет публичным. Панель `/admin/` через интернет-шлюз по-прежнему закрыта. Проверьте доступность `/api/status` с наблюдателя. Внутренний HTTPS-шлюз требует скопировать на наблюдатель только **публичный** `root.crt` из `data/internet-gateway/caddy-data/caddy/pki/authorities/local/`; `root.key`, другие ключи и всю папку `data` не копируйте. Имя или IP в URL должны совпадать с сертификатом. TLS-проверку отключать нельзя.

## Запуск

1. Скопируйте `discord_monitor.py` и `discord-monitor.example.json` на независимое устройство. Скопируйте пример в отдельный локальный файл, например `discord-monitor.json`, и заполните адрес `https://ВАШ_СЕРВЕР:8765/api/status`, два **новых** webhook и интервал 15–3600 секунд. Для внутреннего CA укажите путь к копии `root.crt` в `server_ca_file`; для обычного публичного сертификата оставьте `null`. HTTP разрешён только для localhost и на том же устройстве не решает задачу Offline при выключении сервера.
2. Ограничьте доступ к JSON только своей учётной записью (на Windows настройте ACL файла и папки; на Linux используйте закрытую папку и `chmod 600`). Он содержит секреты открытым текстом. Не храните его в синхронизируемой общей папке. Рядом автоматически создаются `discord-monitor-state.json` и lock-файл; сохраняйте их при перезагрузках. В state не записываются URL webhook, пароли, UID, ключи или данные подписок.
3. На независимом Windows-устройстве запустите `py -3 discord_monitor.py --config "C:\путь\discord-monitor.json"`; на Linux — `python3 discord_monitor.py --config /путь/discord-monitor.json`. Оставьте процесс работать и настройте его автозапуск средствами ОС. Запускайте **только один** экземпляр для этих webhook, в том числе между разными компьютерами. Локальная блокировка не защищает от второго наблюдателя на другом хосте.

Наблюдатель создаёт одно сообщение со статусом, последней опубликованной стабильной версией лоадера и продуктами. Обычные изменения редактируют его; при перезапуске сохранённое предыдущее сообщение удаляется, затем создаётся новое. После двух неудачных проверок подряд действующий Online меняется на Offline; восстановление отражается при успешной проверке. До ответа GitHub версия может быть неизвестна, а при Offline показываются последние сохранённые статусы продуктов. Публичный каталог возвращает не более 100 продуктов; сообщение также ограничивается размером Discord и показывает число остальных продуктов, включая не вошедшие в каталог. Чтобы увидеть их статусы, используйте панель администратора.

Второй webhook получает только короткие сообщения о **новых опубликованных стабильных релизах** Eternal Core и `rmfish-product`; первый запуск запоминает текущие версии без рассылки старых событий. Это не журнал установок на компьютерах клиентов. При потере ответа Discord доставка не может быть гарантирована ровно один раз: чтобы не спамить, событие не повторяется при неопределённом результате. Явный отказ или ограничение частоты повторяется при следующем цикле.

Если ответ на создание основного сообщения потерян или процесс прервался во время создания, автоматическое создание останавливается, чтобы не создать дубликаты. Проверьте канал вручную. Остановите наблюдателя; удалите возможное созданное сообщение, сделайте копию `discord-monitor-state.json` и в оригинале задайте `"message_id": null, "create_pending": false`; затем запустите снова. При замене webhook старым токеном новая ссылка удалить старое сообщение не может — удалите его вручную. Удаление state без проверки канала также может оставить дубликат.

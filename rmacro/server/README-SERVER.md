# Eternal Core Server · release v1

Отдельный сервер с SQLite и веб-панелью администратора. Аккаунтов или паролей по умолчанию нет. Нужны Windows 10/11, Python 3.9 или новее и постоянно включённый компьютер с сервером. Дополнительные Python-пакеты и отдельная СУБД не нужны. Серверный архив, база и резервные копии предназначены только владельцу, не пользователям лоадера.

## Важно: выбран HTTP только для локальной сети

По умолчанию сервер слушает **`192.168.0.105:8765`**, лоадер подключается к нему же, а панель находится по адресу **http://192.168.0.105:8765/admin/**. Этот адрес должен быть назначен сетевому интерфейсу именно серверного компьютера; иначе сервер не запустится. Устройствам нужна сетевая доступность этого адреса, разрешение TCP-порта 8765 в брандмауэре и синхронизированные часы сервера. Задайте в брандмауэре разрешение только для доверенной локальной подсети.

**HTTP не шифрует логины, пароли, токены и ключи.** Любой, кто может перехватить трафик сети, способен их прочитать. Используйте доверенную изолированную LAN, не применяйте этот режим в общедоступной Wi-Fi-сети, не настраивайте проброс порта и не открывайте его в интернет. Ограничение HTTP конкретным частным интерфейсом, допустимым Host и частным/loopback IP подключившегося узла — дополнительная проверка, **не замена брандмауэру или VPN**: NAT, прокси и скомпрометированное устройство могут обойти сетевое предположение. Для публичного доступа нужен доверенный HTTPS, см. ниже. Не используйте пароли от других сервисов.

## Первый запуск

1. Распакуйте серверный ZIP в отдельную доступную для записи папку, не в публичную веб-папку. Установите Python 3 с Python Launcher или `python` в PATH.
2. Запустите `SETUP-ADMIN.bat`: создайте логин и уникальный пароль не короче 12 символов. Пароль при вводе не отображается. После создания администратор автоматически получает отдельный UID для лоадера; логин и пароль те же, что у сайта. Подписка автоматически **не выдаётся**.
3. Убедитесь, что адрес `192.168.0.105` назначен серверному ПК, а сеть и брандмауэр настроены, как описано выше. Запустите `START-SERVER.bat` и оставьте окно открытым. База находится в `data\rmacro.db`; закрытие окна или выключение ПК останавливает сервер.
4. Откройте панель по указанному выше LAN-адресу, войдите. Можно создать пользователей, игры и макросы, выбрать аккаунт и выдать ему время или создать ключ. UID назначается автоматически. Пароли и ключи передавайте по отдельному защищённому каналу.
5. Раздавайте только содержимое клиентского архива. `EternalCore.exe` по умолчанию уже настроен на этот LAN-сервер; адрес не отображается в самом лоадере. Проверьте работу с другого ПК. Владелец может выдать администратору подписку по его UID или активировать ключ в профиле лоадера.

В панели доступны поиск по UID/логину, выдача и замена срока подписки, отзыв, блокировка, смена пароля, переименование обычного пользователя и сброс HWID. Сброс HWID, блокировка и административная смена пароля завершают сессии лоадера. У администратора блокировка этой карточки блокирует вход в **лоадер**, но не сайт; сброс его пароля меняет единый пароль сайта и лоадера и завершает сессии обоих. При смене собственного пароля из лоадера требуется старый пароль; текущая сессия сохраняется, остальные пользовательские и все сессии сайта администратора завершаются.

## Ключи подписок

В разделе «Ключи доступа» выберите игру/продукт, **срок самой подписки**, дату и время, до которого допускается активация, и три лимита:

- **Уникальных людей** — максимальное число разных UID, которые могут использовать ключ.
- **Всего активаций** — общее количество использований, включая повторные одним UID.
- **На одного человека** — сколько раз один UID может применить этот ключ; значение не больше общего лимита.

Каждая успешная активация расходует одну общую активацию и прибавляет срок к существующему окончанию активной подписки или к текущему времени для истёкшей/отсутствующей. Дата активации не является датой окончания подписки. Дата вводится в местном времени браузера; фактическое сравнение и срок определяют часы сервера. Истёкший, отключённый или исчерпанный ключ не активируется. Выключение ключа не отнимает уже выданное время. Проверка лимитов, запись использования и продление выполняются одной транзакцией, в том числе при одновременных запросах.

Полный случайный ключ показывается **только один раз при создании**; сохраните его перед закрытием страницы. Сервер хранит SHA-256 ключа и короткую подсказку, не полный ключ. Владелец может отключить ключ; полученную подписку при необходимости отзывают отдельно в карточке пользователя. При потере ответа лоадер повторно использует идентификатор текущей попытки, поэтому повтор в том же окне не добавит срок дважды. После перезапуска перед повтором проверьте подписку: идентификатор незавершённой попытки не сохраняется.

## Обновление со старого RMacro

1. Остановите старый сервер и сделайте надёжную копию всей папки `data` (`BACKUP.bat` создаёт согласованную копию БД). Распакуйте новый сервер отдельно и перенесите существующий `data\rmacro.db` и, при закрытом сервере, его необходимые файлы состояния. Не перезаписывайте и не удаляйте работающую базу без проверенной копии.
2. При первом запуске схема обновится автоматически: существующие UID пользователей, подписки, привязки и действующие сессии сохраняются. Новый UID администратора появляется без автоматической подписки. Старые продукты сохраняются в каталоге и остаются привязаны к играм.
3. Раньше сайт и лоадер имели разные учётные записи. Если у старого пользователя и администратора совпадает логин, их **не объединяют автоматически**, даже если пароли одинаковы: старый UID и его подписки остаются у старого пользователя. В панели показаны обе карточки и предупреждение о конфликте. Если пароли разные, администратор входит со своим паролем, а старый пользователь — со своим. Если пароли одинаковы, при входе приоритет у администратора: выберите старого пользователя по UID и задайте ему новый логин через форму «Изменить логин». UID и подписки сохранятся; при переименовании его сессии завершатся. Никакое время не переносится автоматически на новый UID администратора; при необходимости выдайте его явно.
4. Обновите и сервер, и клиент. Локальная папка совместимости `%LOCALAPPDATA%\RMacro` сохраняется, но при изменении адреса старый сохранённый токен не передаётся новому серверу и потребуется вход заново. Старые beta-клиенты не умеют активировать ключи или менять пароль в профиле.

## Изменение адреса лоадера

Текущий адрес уже встроен в клиент. Если инфраструктура изменится, запустите `CONFIGURE-LOADER.bat`, укажите путь к исходному `EternalCore.exe`, полный новый URL и путь результата (по умолчанию `configured-client\EternalCore.exe`). Скрипт создаёт новую копию и не перезаписывает исходный или существующий файл результата. В клиентской папке замените EXE на настроенный, оставив рядом оба аварийных BAT и `INSTRUCTIONS.txt`.

HTTP в клиенте допускается только для loopback или буквального частного IPv4 RFC1918; для доменов и публичных адресов нужен HTTPS. Адрес не отображается в лоадере, но записан в EXE и виден при анализе файла или сети — **это не секрет**. Не включайте в адрес пароли или ключи. Настроенная копия не имеет цифровой подписи. Сервер и лоадер не становятся публичными сами по себе.

Для локальной проверки на серверном ПК можно запустить `START-SERVER.bat --host 127.0.0.1`, но для такого запуска нужно отдельно настроить копию клиента на `http://127.0.0.1:8765`: на другой машине этот адрес означает её саму.

## Публичный доступ: только HTTPS

Для доступа через интернет нужен домен, действительный доверенный TLS-сертификат, DNS, брандмауэр и, возможно, настройки маршрутизатора. Не открывайте LAN HTTP в интернет и не отключайте проверку сертификата в клиенте.

Вариант — отдельный HTTPS-прокси на том же ПК. Например, с Caddy и собственным доменом `macro.example.com`:

```bat
START-SERVER.bat --host 127.0.0.1 --allowed-host macro.example.com
```

```text
macro.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

Настройте DNS, доступ и сертификат Caddy. Открывайте только HTTPS-прокси, не порт Python-сервера. В клиент через `CONFIGURE-LOADER.bat` встраивается `https://macro.example.com`. Ограничьте `/admin/` через VPN/IP и включите внешнюю защиту от перебора; встроенный лимит не заменяет WAF и за обратным прокси может учитывать все подключения как один IP.

Либо сервер может обслуживать TLS сам:

```bat
START-SERVER.bat --host 0.0.0.0 --port 8443 --allowed-host macro.example.com --tls-cert "C:\secure\fullchain.pem" --tls-key "C:\secure\privkey.pem"
```

Для сертификата необходимы настройка и регулярное обновление; закрытый ключ, база и резервные копии не должны попадать в Git или клиентский архив. Панель и API используют один адрес; необходимы дополнительные защита, мониторинг и резервирование. Независимый аудит безопасности не проводился.

## Резервирование и ограничения

- `BACKUP.bat` делает согласованную SQLite-копию в `data\backups\`. Защитите базу, копии и сам серверный ПК средствами ОС и делайте отдельные офлайн-копии. В базе хранятся логины, хеши паролей, хеши токенов и ключей, привязки и подписки.
- Для восстановления остановите сервер, сохраните старую папку `data`, удалите старые файлы `rmacro.db-wal`/`rmacro.db-shm` и поместите нужную копию под именем `data\rmacro.db`. Восстановление старой копии откатывает подписки, активации и сессии. Не запускайте несколько расходящихся копий одной базы.
- `RESET-ADMIN.bat` локально меняет единый пароль администратора и завершает сессии сайта и лоадера. Пользовательские сессии действуют до 30 дней, административные — до 12 часов, если не отозваны раньше.
- Пароли — PBKDF2-HMAC-SHA256 с солью; случайные токены и ключи — SHA-256. HWID — псевдонимный хеш идентификатора Windows, его можно подделать.
- Проверка подписки при запуске и во время работы запрашивает остановку RMFish при отзыве или примерно через 90 секунд без подтверждения. Это не прерывает зависший системный вызов и не является защищённой от модификации DRM. Добавление записи в каталог не добавляет реализацию макроса: текущий клиент запускает только RMFish. Реальная GTA5 и физические горячие клавиши не проверены.

# RMacro Server · предварительная версия

Отдельный сервер с локальной SQLite-базой и веб-панелью администратора. Нет готового пароля, облачной базы или регистрации: пользователей создаёт администратор. Для работы нужен компьютер с **Windows 10/11**, [Python 3.9 или новее](https://www.python.org/downloads/windows/) и включённый компьютер с запущенным сервером. Дополнительные Python-пакеты и установка СУБД не нужны.

## Первый запуск на своём Windows-компьютере

1. Распакуйте **серверный ZIP** в отдельную папку, доступную для записи. Не размещайте её в публичной веб-папке и никому не раздавайте серверную папку после создания базы.
2. Установите Python 3 (с Python Launcher или `python` в PATH). Запустите **`SETUP-ADMIN.bat`** и создайте логин и уникальный пароль администратора не короче 12 символов. При вводе пароль не отображается. Пароля по умолчанию нет.
3. Запустите **`START-SERVER.bat`** и оставьте его окно открытым. База создаётся в `data\rmacro.db`; выключение ПК или закрытие окна останавливает сервер.
4. На том же компьютере откройте **http://127.0.0.1:8765/admin/**, войдите как администратор. Создайте пользователя, выберите его и добавьте время для RMFish. UID назначается автоматически; первоначально подписки нет. Передайте пользователю его логин и пароль через защищённый канал.
5. Запустите `RMacro.exe` на том же компьютере и укажите сервер `http://127.0.0.1:8765` либо настройте HTTPS для других компьютеров, как описано ниже. На другой машине `127.0.0.1` указывает на **неё саму**, а не на ваш сервер.

Панель показывает UID и факт привязки устройства, но не сам отпечаток. Она умеет создавать аккаунты и продукты, добавлять минуты/часы/дни, отзывать подписку, блокировать аккаунт, менять пароль и сбрасывать HWID. Сброс HWID, смена пароля и блокировка завершают текущие сессии. Следующий успешный вход после сброса привязывает новое устройство. Для поиска используйте логин или UID, в том числе с ведущими нулями. Показывается до 500 совпадений.

## Удалённый доступ: HTTPS обязателен

По умолчанию сервер слушает только `127.0.0.1`, поэтому из интернета и локальной сети он не доступен. Сам по себе запуск BAT **не делает ваш ПК публичным**. Лоадер не отправляет логины, пароли или токены по HTTP на удалённый адрес. Для других ПК нужен домен, действительный доверенный TLS-сертификат и доступ по сети; могут понадобиться публичный IP, настройка DNS, брандмауэра и переадресации портов роутера. Не отключайте проверку сертификата и не открывайте этот HTTP-порт напрямую в интернет.

Один вариант — обратный HTTPS-прокси на том же ПК (например, Caddy с автоматически полученным сертификатом). Допустим, ваш домен — `macro.example.com` (**замените пример реальным доменом**):

1. Оставьте Python-сервер локальным, но разрешите точное имя домена в заголовке Host. Запустите из `cmd` в серверной папке:
   ```bat
   START-SERVER.bat --allowed-host macro.example.com
   ```
2. В отдельно установленном Caddy настройте, например:
   ```text
   macro.example.com {
       reverse_proxy 127.0.0.1:8765
   }
   ```
   Настройте DNS/доступ снаружи, порты и сертификат по инструкции Caddy. Держите и Python-сервер, и прокси запущенными. Доступ извне должен идти **только через HTTPS-прокси**, порт 8765 наружу не открывать.
3. Администратор открывает `https://macro.example.com/admin/`, пользователи вводят `https://macro.example.com` в RMacro. Действительный сертификат должен соответствовать имени. Ограничьте доступ к `/admin/` по VPN/IP на прокси и включите защиту от перебора: встроенный лимит попыток не заменяет WAF. При обратном прокси лимит может учитывать все подключения как один IP.

Вариант без прокси: сервер может сам обслуживать HTTPS. Получите действительные файлы PEM-сертификата и ключа, затем запустите:

```bat
START-SERVER.bat --host 0.0.0.0 --port 8443 --allowed-host macro.example.com --tls-cert "C:\secure\fullchain.pem" --tls-key "C:\secure\privkey.pem"
```

Запрет внешнего HTTP установлен программно. Для TLS потребуются настройка и регулярное обновление сертификата, домена, порта, роутера и брандмауэра. Никогда не раздавайте закрытый ключ и не добавляйте его в Git. Панель администратора и API находятся на одном адресе: для эксплуатации необходимы дополнительные меры защиты, мониторинг и резервирование. Это начальная версия, не проверенная независимым аудитом и не рассчитанная на крупный публичный сервис.

## Сохранность и восстановление

- **`BACKUP.bat`** делает согласованную копию работающей SQLite-базы в `data\backups\`. База и копии содержат логины, хеши паролей, токены сессий в виде хешей, привязки и подписки. Храните их закрыто, ограничьте права NTFS и делайте отдельные офлайн-копии. Не кладите их в ZIP клиента/Git и не отправляйте покупателям.
- Для восстановления остановите сервер, сохраните старую папку `data`, удалите старые файлы `rmacro.db-wal`/`rmacro.db-shm` и поместите нужную копию под именем `data\rmacro.db`, после чего запустите сервер. Восстановление старой копии откатывает и подписки, и сессии.
- **`RESET-ADMIN.bat`** локально меняет пароль существующего администратора и завершает его сессии. Это доступ к базе: защищайте сам серверный компьютер.
- Сессия пользователя действует до 30 дней, администраторская — до 12 часов; после этого нужен новый вход. Удалённый сброс, смена пароля и блокировка отзывают сессии раньше.
- Пароли хранятся как PBKDF2-HMAC-SHA256 с индивидуальной солью; случайные токены — в виде SHA-256. HWID — псевдонимный SHA-256 идентификатора Windows, а не пароль и не надёжная аппаратная защита. Не используйте пароли от других сервисов.
- Время подписки рассчитывает сервер по его UTC-часам; проверьте синхронизацию времени Windows. Продление прибавляется к текущему окончанию активной подписки, а истекшая начинается с текущего времени. При резервном копировании/переносе базы не делайте работающие копии одного сервера с расходящимися данными.

## Ограничения

RMacro проверяет подписку при открытии RMFish и периодически во время работы. При отзыве, блокировке или невозможности подтвердить доступ в течение примерно 90 секунд он запрашивает остановку и блокирует новый запуск. Это не прерывает зависший системный вызов. Серверные проверки усложняют обычное использование без подписки, но **не являются защищённой от модификации DRM**: клиент работает у пользователя, а исходный код и прежние автономные версии RMFish уже опубликованы. Новые продукты не начнут запускаться без реализации в лоадере.

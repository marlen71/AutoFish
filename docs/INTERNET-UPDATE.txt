Eternal Core 1.2.0 — ручное включение HTTPS для клиентов из интернета

ВАЖНО: сам по себе этот ZIP или автообновление лоадера не откроет доступ из интернета. Шлюз, порты и новый клиент нужно настроить вручную на серверном ПК. Не отправляйте пользователям серверный архив, data, базу, резервные копии или закрытый TLS-ключ.

1. Временно отключите проброс старого HTTP-порта 8765 наружу. На серверном ПК запустите BACKUP.bat, затем остановите старое окно START-SERVER.bat. При остановленном сервере отдельно сохраните копию всей папки data и старого server.py.
2. В уже установленной папке сервера замените server.py новым файлом из этого ZIP. Положите рядом internet_gateway.py, CONFIGURE-INTERNET.bat и START-INTERNET.bat. Остальные файлы, включая RUN-PYTHON.bat, папку static и всю папку data с базой, не удаляйте и не перезаписывайте. Эта инструкция в корне сервера для работы не нужна.
3. Отдельно распакуйте новый клиентский ZIP 1.2.0. Запустите в папке сервера CONFIGURE-INTERNET.bat. Введите свой публичный IPv4 БЕЗ протокола и порта и путь к EternalCore.exe из распакованного клиентского ZIP. С согласия владельца скрипт скачает Caddy 2.11.9 из официального GitHub и проверит SHA-256 архива. Он не меняет службу Windows, роутер или брандмауэр.
4. Скрипт создаст новую копию EXE в configured-client\internet-...\EternalCore.exe и покажет полный путь. В КОПИИ клиентского архива замените EternalCore.exe именно этой копией, остальные файлы архива сохраните. Раздайте людям весь клиентский комплект. Старые копии и их автообновление сохраняют старый адрес, поэтому для перехода требуется один раз вручную раздать настроенный EXE. При смене адреса пользователям понадобится снова войти.
5. На роутере и в брандмауэре направьте TCP 8765 и TCP 80 на серверный ПК. 8765 используется для HTTPS, 80 — только для проверки выпуска и продления сертификата Let's Encrypt; API и панель по обычному HTTP наружу не предоставляются. Не направляйте наружу TCP 18765 — это локальный сервер. Если порт 80 занят или недоступен провайдером, получение сертификата не заработает; не отключайте проверку сертификата.
6. Запустите START-INTERNET.bat и оставьте окно открытым. Сервер внутри слушает только 127.0.0.1:18765; админ-панель на самом серверном ПК: http://127.0.0.1:18765/admin/. Старый адрес LAN-панели на 8765 в этом режиме больше не используется. HTTPS-шлюз публикует только необходимые пути API лоадера, не сайт и не API администратора. Закрытие окна или выключение ПК останавливает сервис.
7. После получения сертификата откройте с ДРУГОЙ сети https://ВАШ_ПУБЛИЧНЫЙ_IP:8765/api/health. Браузер должен без предупреждения о сертификате показать JSON с ok: true. Если не открывается или выдаёт ошибку сертификата, не вводите пароли: сохраните текст ошибки и последние строки окна шлюза без паролей/токенов и обратитесь к администратору. Проверка из той же сети через внешний IP может не работать из-за NAT loopback; проверяйте мобильным интернетом или с другого ПК.

Сертификат Let's Encrypt для IP действует 160 часов (немногим больше 6 дней). Caddy обновляет его автоматически, только пока программа запускается и TCP 80 снаружи доступен; храните data\internet-gateway\caddy-data и закрытый ключ в секрете. При потере доступа к центру сертификатов, закрытии порта, выключенном ПК или изменении IP обновление может не выполниться, и клиенты потеряют связь. Если публичный IP изменился, старый адрес может перейти другому лицу: попросите пользователей не вводить данные в старой копии, заново настройте шлюз и клиент, раздайте новый EXE. Статический IP или собственный домен надёжнее.

Новый лоадер проверяет TLS средствами Windows и не отключает проверку сертификата. Адрес не показывается в его интерфейсе, но доступен в файле и сетевом трафике — он не является секретом. Сервер, база, шлюз и сайт автоматически не обновляются. Публичный сервис не проходил независимый аудит: защитите ПК, применяйте сложные пароли и отдельно контролируйте доступ; ограничение в самом приложении не заменяет сетевой защиты.

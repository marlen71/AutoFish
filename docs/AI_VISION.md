# AI-зрение Eternal FishMod — архитектура, модели, офлайн-работа

v1.24.0. Всё описанное — **локально**: CPU/интегрированная графика, офлайн,
никаких облачных API и телеметрии. Модели **никогда не скачиваются сами**.

---

## 1. Зачем и что это

Конвейер наблюдения (`ai/`) смотрит на кадры легаси-захвата и публикует
**структурированные события** (инвентарь открылся, мини-игра началась, экран
сменяется, «что-то изменилось и я не знаю что»). Он **не кликает и не жмёт
клавиши** — ввод остаётся у проверенной легаси-логики. Если модели нет,
приложение полностью функционально на шаблонах (rod/rod2/bait, красная строка
меню, детектор игрового курсора).

## 2. Компоненты

| Файл | Ответственность |
|---|---|
| `ai/config.py` | все ai_* ключи конфига (один источник дефолтов) |
| `ai/frame_router.py` | кадр+метаданные (id/время/монитор/масштаб), стратегия «последний кадр», дедупликация, быстрый/медленный путь |
| `ai/runtime.py` | ONNX Runtime CPU: ленивая загрузка, потоки, прогрев, замер мс |
| `ai/model_manager.py` | манифест моделей, sha256, честные статусы (нет модели/битая) |
| `ai/detector.py` | адаптер детектора (layout `nms5`), реестр классов, NMS; NullDetector без модели |
| `ai/ocr.py` | RapidOCR (ONNX) — опция; региональный OCR, нормализация, дедупликация |
| `ai/change_detector.py` | сетка 16×16, гистерезис, отсев ровной засветки, флаг screen_transition |
| `ai/state_classifier.py` | правила + подтверждение N кадров; состояния из ТЗ; честный `unknown` |
| `ai/tracker.py` | трекинг детекций по IoU (устойчивые id) |
| `ai/event_fusion.py` | слияние сигналов → VisionEvent с кулдаунами |
| `ai/event_bus.py` | потокобезопасная шина: подписки, изоляция ошибок, история, stale-reject |
| `ai/pipeline.py` | один воркер-демон: забирает свежий кадр, гоняет модули, публикует события |
| `ai/diagnostics.py` | events.jsonl (ротация), снимки неизвестного с лимитами (файлы/МБ/диск) |

Интеграция в приложение: секция **8B** в `eternal_fishmod.py` — `_ai_frame_source`
(кадр из ЕДИНОГО захвата, второй процесс не запускается), `_ai_hints` (дешёвые
легаси-подсказки), `ai_start/ai_stop/ai_restart/ai_status/ai_rod_find/ai_report`.
Страница GUI **«AI-ЗРЕНИЕ»** (6-я плитка) — статус и настройки.

## 3. Потоки данных

```
легаси-захват (DXGI/GDI, 1 процесс)
        │  grab_full() + метаданные
        ▼
  FrameRouter.submit() ─── быстрый путь (мини-игра) остаётся в легаси
        │ медленный путь: слот на 1 кадр (новый вытесняет старый, счётчик dropped)
        ▼
  воркер VisionPipeline (daemon-поток, ОДИН)
   ├─ change_detector (каждый свежий кадр, ~5-20 мс @1080p)
   ├─ ONNX-детектор (по частоте ai_detect_fps, по умолчанию 2 к/с)
   ├─ OCR (по частоте ai_ocr_fps, только регионы; выкл. по умолчанию)
   ├─ state_classifier (правила + легаси-подсказки + подтверждение)
   └─ event_fusion → VisionEvent → EventBus → подписчики (журнал/GUI)
                                   └→ diagnostics (jsonl + снимки unknown)
```

Гарантии: GUI никогда не обновляется из воркера (он **опрашивает** `ai_status()`
в своём такте); отказ модуля помечает его деградировавшим и не роняет цикл;
паника/стоп легаси в приоритете; мышь AI не трогает вообще.

## 4. Установка зависимостей (всё опционально для AI)

```bat
:: базовый бот работает и так; для AI-детектора:
pip install onnxruntime==1.20.*
:: для OCR (тяжелее, качает onnxruntime сам):
pip install rapidocr-onnxruntime
```

`requirements.txt` намеренно НЕ тянет их автоматически. Офлайн-машина: поставьте
wheels заранее (`pip download onnxruntime -d wheels/` на машине с сетью, затем
`pip install --no-index --find-links=wheels/ onnxruntime`).

Офлайн-проверка: `python scripts/ai_smoke_test.py` — зависимости, модель,
тайминги, 20 циклов конвейера. Сеть не используется.

## 5. Модели: формат, установка, проверка

Каталог: `ai/models/` (или `CFG["ai_model_dir"]`). Манифест `ai/models/manifest.json`:

```json
{"version": 1, "models": {
  "detector": {"file": "rod_detector.onnx", "sha256": "<hex 64>",
               "version": "1.0.0", "input": [1, 3, 640, 640],
               "layout": "nms5",
               "classes": ["inventory_window", "fishing_rod", "bait_icon", "..."]}}}
```

* `sha256` обязателен: менеджер отбракует чужой/битый файл (`bad_checksum`).
* **Контракт выхода `nms5`**: тензор `[1, M, 5+C]`, строка =
  `[cx, cy, w, h, obj, class_0..class_{C-1}]`, все значения после sigmoid,
  координаты — доли входа модели. Экспорт YOLO-подобных моделей под этот формат
  см. `datasets/README.md`.
* OCR: RapidOCR сам содержит модели — отдельная установка не нужна.
* **ВАЖНО (честно)**: в репозитории НЕТ обученной игровой модели. Универсальная
  предобученная модель объекты Skyrim не знает. Пока вы не обучите модель на
  своих скриншотах, детектор честно вернёт «модель не установлена», а бот будет
  работать шаблонами. Никаких выдуманных распознаваний.

## 6. Конфигурация (ключи `ai_*`, миграция аддитивная)

| Ключ | Дефолт | Смысл |
|---|---|---|
| `ai_enabled` | `False` | конвейер наблюдения (стартует/останавливается вместе с рыбалкой) |
| `ai_mode` | `legacy` | поиск удочки при экипировке: `legacy` (шаблоны) / `ai` (ONNX, фолбэк шаблоны) / `hybrid` (шаблоны первыми, AI спасает при промахе) |
| `ai_fullscreen` | `True` | полный экран в медленном контуре |
| `ai_change_detect` | `True` | лёгкий детектор изменений |
| `ai_ocr_enabled` | `False` | OCR (нужен rapidocr) |
| `ai_ocr_fps` | `1.0` | частота OCR |
| `ai_detect_fps` | `2.0` | частота полного детектирования (0.5–5) |
| `ai_conf` | `0.45` | порог уверенности детектора |
| `ai_state_confirm` | `3` | кадров подтверждения смены состояния |
| `ai_threads` | `0` | потоки ONNX (0 = авто) |
| `ai_snapshots` | `True` | снимки НЕИЗВЕСТНЫХ событий |
| `ai_snap_max_mb` / `ai_snap_max_files` | `200` / `40` | лимиты хранилища снимков (+ стоп при <300 МБ свободно) |
| `ai_model_dir` | `""` | свой каталог моделей |

Старые конфиги: недостающие ключи получают дефолты, пользовательские значения
не трогаются, `cfg_version` не меняется.

## 7. Режимы наблюдения

**Только наблюдение (по умолчанию)**: поставьте галку «AI-наблюдение» на странице
«AI-ЗРЕНИЕ» (или `"ai_enabled": true`). Запустите рыбалку F8 — в журнале появятся
строки `🤖 AI: …` (открытие инвентаря, переходы, неизвестное), в `diagnostics/` —
events.jsonl и снимки. Бот ведёт себя как раньше, кликает только легаси.

**Legacy / AI / Hybrid** (экипировка):
* `legacy` — как в 1.21–1.23 (шаблонный каскад rod+rod2, края, CLAHE);
* `ai` — сначала ONNX-детектор (класс `fishing_rod`); нет модели/не нашёл →
  автоматический спуск в шаблонный каскад (одна строка в журнале, без спама);
* `hybrid` — шаблоны первыми, AI подключается при их промахе.
Координаты во всех режимах — те же экранно-референсные, что и у легаси; клик
по-прежнему делает `_aim_click`/`_ui_click` с зрительным подтверждением.

## 8. Диагностика

* `diagnostics/events.jsonl(.1/.2)` — все события (тип, кадр, уверенность, bbox).
* `diagnostics/snapshots/unk_*.png` — кадры неизвестных событий (лимиты §6).
* Кнопка **«Журнал AI»** — последние 12 событий + счётчики в журнал бота.
* **«Перезапустить AI»** — подхватить новую модель/настройки без перезапуска бота.
* F9 (снимок) — как раньше, плюс легаси-диагностика не изменена.

## 9. Производительность (замеры, а не обещания)

Эталонная среда CI (1 vCPU): детектор изменений ~20 мс/кадр 1080p; ONNX 64×64
синтетика ~0.05 мс/инференс (конвейерная проверка, не игровая модель). Реальная
YOLO-модель 320–640px на пользовательском CPU обычно даёт 2–5 к/с — это и есть
стартовая цель `ai_detect_fps`. Мини-игра НЕ зависит от AI: свой поток, свой
ритм захвата; FrameRouter отбрасывает кадры, которые AI не успел разобрать
(счётчик «Пропущено» на странице AI).

## 10. Известные ограничения

1. Нет обученной игровой модели — распознают только шаблоны легаси; AI-детектор
   ждёт ваш датасет (см. `datasets/README.md`).
2. OCR выключен по умолчанию; rapidocr — заметная зависимость.
3. Классификатор состояний — правила; обучаемый классификатор — будущая работа.
4. Неизвестное событие — это сигнал «посмотрите сюда», а не описание происходящего.
5. GDI-захват (~8 fps в поле) ограничивает частоту всего зрения, AI не исключение.

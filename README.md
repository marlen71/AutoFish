# Eternal FishMod

Полуавтомат рыбалки для Skyrim с кастомным RP-сервером (Sovngarde и аналоги): сам берёт
удочку из инвентаря, закидывает, **проходит мини-игру «Вылавливание рыбы»** и следит за
наживкой. Ходить, торговаться и выбирать место — по-прежнему тебе.

**Текущая версия:** см. [`VERSION`](VERSION) (она же в шапке окна, в пилюле-оверлее и в лаунчере).

## 1. Что изменилось в 1.5.0 (коротко)

| Область | Было (1.4.0) | Стало (1.5.0) |
|---|---|---|
| Резервный захват | `mss`-пакет (явный режим) — ~12 мс на кадр, весь монитор, лишняя зависимость | **вырезан полностью**; вместо него — собственный **GDI-захват** (`_GdiBackend`, ctypes: GetDC + BitBlt/GetDIBits): ноль зависимостей, кроп региона, DC живёт в потоке; кандидаты: `dxcam → bettercam → gdi` |
| Конфиг со старым `"capture_backend": "mss"` | бот навсегда оставался в резерве | мигрируется на `auto` при загрузке, в журнал пишется `⚙ Конфиг: значение … устарело` |
| Регулятор мини-игры | ПИД по ПОЛОЖЕНИЮ зоны | **каскад**: внешний контур назначает желаемую СКОРОСТЬ зоны (профиль подхода по тормозному пути), внутренний ПИД отрабатывает её; измеритель **точки равновесия** (`hover_adapt`) сам находит «сколько держать, чтобы зона стояла» |

## 2. Структура проекта

```
eternal_fishmod/
  eternal_fishmod.py      <- ВЕСЬ код бота одним файлом (захват, ПИД, инвентарь, GUI, звуки,
                             хоткеи, локализация, конфиг). Разделы пронумерованы комментариями.
  launch.py               <- лаунчер-обёртка: проверки окружения + запуск бота
  start.bat               <- запуск двойным кликом (с консолью); файл намеренно ASCII+CRLF, см. §3.4
  start_admin.bat         <- то же, но сразу с правами администратора (UAC)
  start.vbs               <- тихий запуск без окна консоли (pythonw)
  requirements.txt        <- dxcam + bettercam (оба DXGI) + opencv/numpy/...
  VERSION                 <- текущая версия, источник истины для релизной автоматизации
  CHANGELOG.md            <- история версий человеческим языком
  README.md
  scripts/
    release.py            <- бамп semver + коммит + тег + GitHub Release (gh или REST)
  .github/workflows/
    release.yml            <- релиз автоматически по пушу тега v*.*.*
  tests/
    test_vision.py         <- офлайн-проверки зрения/ПИДА/локализации на скриншотах (без Windows)
  templates/               <- картинки-шаблоны (rod.png, bait.png, inv_header.png, hud_*.png)
  sounds/                  <- сюда можно положить свои start/end/alert/catch.wav
  fishmod_config.json       <- создаётся при первом запуске
  fishmod_stats.json        <- статистика за всё время
  fishmod.log               <- журнал (пишется и в консоль, и в файл)
```

**Переводы лежат в самом `eternal_fishmod.py`** (словарь `STRINGS`), а не в `lang/*.json`:
так проще держать один файл-приложение и не плодить внешние зависимости от путей.

## 3. Установка и первый запуск

### 3.1. Самый простой путь (Windows)
1. Установи Python 3.10–3.12 с [python.org](https://www.python.org/downloads/) — **поставь галочку
   «Add Python to PATH»** (иначе `start.bat` его не найдёт).
2. Распакуй архив релиза (или клонируй репозиторий) в любую папку, например `D:\AutoFish`.
3. Дважды кликни **`start.bat`**. Лаунчер:
   * проверит версию Python;
   * найдёт недостающие библиотеки и сам поставит их через `pip install -r requirements.txt`
     (спросит разрешение; `start.bat --yes` — без вопроса);
   * проверит, есть ли права администратора, и предложит перезапуститься через UAC;
   * запустит `eternal_fishmod.py` отдельным процессом.
4. В игре нажми **F8**. При первом запуске бот попросит откалиброваться (см. §5).

Другие способы запуска:

| Команда | Что делает |
|---|---|
| `python launch.py` | обычный запуск через лаунчер |
| `python launch.py --yes` | ставить зависимости без вопроса |
| `python launch.py --no-install` | только проверить, ничего не ставить |
| `python launch.py --restart` | автоперезапуск бота, если он упал (Ctrl+C — выход) |
| `python launch.py --lang ru` | язык сообщений лаунчера (`ru`/`en`/`ua`; по умолчанию берётся из конфига) |
| двойной клик `start.vbs` | то же, что `start.bat`, но **без окна консоли** (через `pythonw`) |
| двойной клик `start_admin.bat` | сразу с правами администратора (UAC-запрос) |
| `python eternal_fishmod.py` | прямой запуск, если зависимости уже стоят |

### 3.2. Вручную (если не хочешь лаунчер)
```bat
pip install -r requirements.txt
python eternal_fishmod.py
```

### 3.3. Права администратора
Если игра (или её лаунчер) запущена от администратора, обычное приложение **не сможет**
отправлять в неё клики `SendInput` и часто — захватывать кадр. Признак: бот «крутит»
мышью, а в игре ничего не происходит. Решение — `start_admin.bat` или
«Правая кнопка на `start.bat` → Запуск от имени администратора».

### 3.4. Почему `start.bat` / `start_admin.bat` / `start.vbs` — только ASCII и CRLF
`cmd.exe` читает `.bat` побайтово и запоминает смещения строк, а `wscript.exe` читает `.vbs`
как ANSI (на русской Windows — cp1251). Если в такой файл попадёт кириллица (или файл будет
с LF-переводами, как принято в Git/Linux), смещения съезжают и начинают выполняться обрезки
соседних строк. Симптомы ровно такие:

```
'не' is not recognized as an internal or external command,
'права' is not recognized as an internal or external command,
'--restart' is not recognized as an internal or external command,
'el' is not recognized as an internal or external command,
Код возврата: 9009
```

Поэтому файлы запуска — служебный трамплин на ~30 строк чистого ASCII с CRLF, а **весь
переведённый и цветной вывод печатает `launch.py`** (Python с UTF-8 обращается корректно).
Инвариант сторожит `python tests/test_launcher_files.py`, а `.gitattributes` гарантирует
CRLF при клонировании на любой ОС.

**Если ошибка всё-таки появилась** (пересохранил файл в редакторе с UTF-8/LF, скопировал
`.bat` куда-то отдельно, скачал не из релиза): возьми оригиналы из архива релиза либо выполни
`git checkout -- start.bat start_admin.bat start.vbs`. Быстрое ручное лечение в Notepad++:
«Кодировки → Преобразовать в ANSI(UTF-8 без BOM)» + «Edit → Document Parameters → Windows (CR LF)»;
в VS Code — правый нижний угол: `CRLF` и `UTF-8`. Как вариант — вообще не трогай `.bat` и запускай
`python launch.py` из папки.

### 3.5. Сборка в один .exe (на будущее, опционально)
```bat
pip install pyinstaller
pyinstaller --onefile --name EternalFishMod --noconsole --add-data "templates;templates" ^
            --icon=icon.ico eternal_fishmod.py launch.py
```
Получится `dist\EternalFishMod.exe`. Нюансы:
* `--noconsole` нужен только для «тихого» запуска; для отладки убери его, чтобы видеть сообщения;
* `--add-data` пакует шаблоны внутрь exe; тогда `BASE_DIR` для `templates/` надо искать через
  `sys._MEIPASS` (в скрипте это одна строка в `BASE_DIR` — при необходимости поправь);
* зависимости (`dxcam`, `opencv-python`, …) PyInstaller подтянет сам, но `keyboard`/`pydirectinput`
  иногда требуют `--hidden-import keyboard --hidden-import pydirectinput`;
* exe всё равно нужно запускать от администратора, если игра elevated;
* антивирусы/SmartScreen могут ругаться на неподписанный exe — это нормально для PyInstaller.

## 4. Как это работает (чтобы понимать, что калибровать)

1. **F8** → бот запоминает активное окно как «окно игры» и работает, только пока оно активно
   (свернул/переключился — пауза, ЛКМ отпускается).
2. Открывает инвентарь (`TAB`), находит шаблон `bait.png` → проверяет наживку.
3. Если удочки нет в руках (не найден `hud_fish.png`) — находит `rod.png` в сетке инвентаря,
   делает **ПКМ** по иконке, ждёт контекстное меню, находит **красную** строку «Выбросить» и
   кликает **на `use_offset[1]` пикселей выше** неё — по пункту «Использовать».
4. `cast_delay` → **ЛКМ** (заброс) → ждёт **появления мини-игры** (не индикатор «ОЖИДАЙТЕ КЛЁВА»,
   он ненадёжен). Поток DXGI в это время уже крутится, поэтому реакция — на следующем кадре.
5. Мини-игра: `analyze()` ищет **реальную** шкалу в кадре (`scale_rect`), затем зелёную
   зону и рыбку. Регулятор — **каскад**: «ошибка → желаемая скорость зоны → ПИД по
   скорости → скважность ШИМ на ЛКМ». ЛКМ в этой игре — **ускорение** зоны (зажал —
   разгоняется вверх, отпустил — падает), поэтому прямым ПИД по положению зону не
   удержать: каскад тормозит заранее (профиль подхода `sqrt(2·stop_acc·дистанция)`),
   интегратор сам находит равновесие, а измеритель равновесия (`hover_adapt`) доливает
   его в bias уже за ~1 с. При красной рамке «РЫБА СРЫВАЕТСЯ» — аварийный комплект
   коэффициентов и догоняшка с учётом инерции.
6. Зона пропала ⇒ рыба считается пойманной ⇒ пауза `post_catch_delay` ⇒ новый цикл.
   Каждые `bait_check_every` рыб — проверка наживки; `no_bite_limit` таймаутов подряд или
   отсутствие наживки ⇒ остановка с объяснением в статусе.

Режимы (страница «Модули»): **«Авто-закидывание удочки»** вкл — полная автоматика;
выкл — бот только проходит мини-игру (закидываешь сам), удобно для тестов калибровки.

## 5. Калибровка

### 5.1. Шаблоны (вкладка «Зрение»)
Нужны файлы в `templates/`: `rod.png`, `bait.png`, `inv_header.png`,
`hud_fish.png`, `hud_bait.png`, `hud_shield.png`.

Как снять свой, если игра/разрешение другие: открой в игре нужное окно, наведи курсор
**в центр иконки** и нажми «Шаблон: удочка» / «Шаблон: наживка» (съём через 4 с). Для
остальных — снимите кадр (F9 → `debug_screen.png`) и вырежи прямоугольник ~28×28 в
`templates/<имя>.png`. Пороги совпадения: `THR` в начале `eternal_fishmod.py` (строка
`THR = {...}`); ниже порог — терпимее к подсветке слота и небольшому смещению, выше — меньше ложных срабатываний.
Внизу блока «Шаблоны» видно текущий score каждого шаблона: `0.97 / 0.90` — ок,
`0.41 / 0.90` — шаблон пора переснять.

### 5.2. Область шкалы мини-игры и рамка срыва
`CFG["bar"] = [x, y, w, h]` — **в эталонных координатах 1920×1080**; для другого разрешения
всё масштабируется автоматически. `bar_pad` — на сколько пикселей расширить кадр вокруг
шкалы: нужно, чтобы видеть красную рамку «РЫБА СРЫВАЕТСЯ» (иначе `slip_thr` никогда
не сработает).

С 1.5.0 калибровка «на глаз» больше не критична:

* **`bar_refine`** (вкл) — каждый кадр границы шкалы сверяются с картинкой: зона/рыба
  измеряются по **реальной** шкале, даже если `CFG["bar"]` сбит на десятки пикселей.
* **`bar_autofit`** (вкл) — если шкала вовсе вылезла из окна захвата (сменилось разрешение,
  масштаб Windows, монитор), бот находит её по всему экрану, правит `CFG["bar"]`,
  сохраняет конфиг и пишет в журнал `📐 Шкала уехала: …`.

Проверить: на странице «Зрение» в превью шкалы зелёная рамка должна
ровно облегать зону, а в состоянии срыва `slip` должен показывать ~100%.

### 5.3. Координаты удочки и кнопки «Использовать» (страница «Настройки»)
Самый надёжный способ — ручные координаты:
1. открой инвентарь в игре;
2. на «Настройки» нажми **📍** в строке «ПКМ удочка:» и **кликни левой кнопкой по иконке
   удочки** в игре — координаты подставятся (и запишутся в буфер обмена);
3. «Задать» — сохранить.
4. То же для «ЛКМ «Использовать»:» — кликни по пункту **«Использовать»** (он верхний,
   тёмный) в открытом контекстном меню.

Если `rod_click_pos` / `use_click_pos` заданы — авто-поиск не используется вовсе.
Если не заданы: удочка ищется шаблоном, а «Использовать» — **над красной строкой**; тонкая
настройка подъёма — степпер **«„Использовать“ ↑, px»** (`use_offset[1]`; по замерам 1920×1080
это ~20 px при высоте строки меню ~37 px).

### 5.4. DPI и два монитора
`SetProcessDpiAwareness(2)` включается при старте, все клики идут в **физических**
пикселях (координаты курсора конвертируются `logical_to_physical()`). Если игра в
окне/на втором мониторе — проверь `capture_monitor` (0 = основной) и `CFG["bar"]`;
захват и клики используют геометрию одного и того же монитора из `ScreenCapture`.

## 6. Проверка, что dxcam действительно работает

Сразу после запуска посмотри:

* **лог** (внизу страницы «Рыбалка» и в `fishmod.log`):
  `🖥 Захват: dxcam (кадр 1920x1080)` — размер кадра пишется именно потому, что бэкенд
  сначала **обязан получить настоящий кадр**: пустой/чёрный кадр = бэкенд не годится;
  при старте мини-игры — `🖥 Поток мини-игры: dxcam, 144 fps, регион 94x573`;
* **страница «Зрение»**, блок «ЗАХВАТ ЭКРАНА»: активный бэкенд (`DXCAM`/`BETTERCAM`/`GDI`),
  реальные **fps** и задержка кадра, размер монитора и масштаб;
* смешанных путей захвата в коде нет — всё идёт через `ScreenCapture`
  (`grab_region` / `grab_ref` / `grab_full` / `wait_frame`).

**Как выбирается бэкенд (с 1.5.0).** `auto` = `dxcam` → `bettercam` → `gdi`. Оба первых —
DXGI Desktop Duplication; `gdi` — собственный резерв на ctypes (BitBlt по региону), без
единой зависимости, для случаев, где DXGI не поднимается в принципе (RDP, виртуалка без 3D,
защищённое окно). Резерв никогда не подменяет DXGI молча: бэкенд и его fps подписаны в
шапке, в журнале и на странице «Зрение», а GDI чуть медленнее и не видит
защищённые от захвата окна. Если не сработал ни один кандидат, бот останавливается с
полным списком причин, например:

```
ни один бэкенд захвата не запустился — dxcam: create(output_color='BGR', output_idx=0):
RuntimeError: DXGI_ERROR_ACCESS_LOST | bettercam: ... не импортирован (ModuleNotFoundError:
No module named 'comtypes') | gdi: …
Что сделать: python -m pip install -U dxcam bettercam (и перезапусти). Если DXGI недоступен
(RDP, виртуалка, окно защищено от захвата) — бот сам возьмёт GDI-резерв; чтобы работать
строго по DXGI, поставь в fishmod_config.json "capture_backend": "dxcam"
```

Те же причины видны и в журнале (`🖥 dxcam: ...`) — это главное, что стоит прочитаться при
проблемах с захватом. Конфиги версий 1.2–1.3 со значением `"capture_backend": "mss"`
мигрируются на `auto` автоматически (в журнале: `⚙ Конфиг: значение … устарело`).

Принудить бэкенд: `CFG["capture_backend"]` = `auto` (dxcam → bettercam → gdi), `dxcam`,
`bettercam` или `gdi`. Частота потока — `CFG["capture_fps"]` (120–144 рекомендуется; ставь
не выше герцовки монитора: DXGI отдаёт кадр на изменение экрана). Обе DXGI-библиотеки
ставятся лаунчером автоматически и дублируют друг друга: не заведётся одна — бот возьмёт
вторую.

При закрытии окна/падении бота дубликатор освобождается (`ScreenCapture.close()` + `atexit`),
так что повторный запуск не упирается в «занятый» DXGI.

## 7. ПИД: как калибровать с нуля

Все коэффициенты — на странице **«Модули»**, правый столбец (и в `fishmod_config.json`).

**Как устроен регулятор (1.5.0).** ЛКМ в мини-игре — это УСКОРЕНИЕ зоны: зажал — зона
разгоняется вверх, отпустил — разгоняется вниз. Поэтому прямой ПИД по положению не
работает (нет демпфирования — зона проскакивает рыбу и «зависает» у края; именно это было
на скриншотах «бот перегоняет зону вверх»). Схема каскадная:

```
ошибка (рыба внутри зоны = 0)  →  v_жел = clamp(vel_gain·e, тормозной_путь, ±vel_max)
скоростная ошибка (v_зоны − v_жел)  →  ПИД (Kp/Ki/Kd)  →  duty 0..1  →  ШИМ ЛКМ
```

* **профиль подхода**: рядом с рыбой желаемая скорость ограничена `sqrt(2·stop_acc·дистанция)` —
  зона ВЪЕЗЖАЕТ в рыбу, а не проскакивает её (тормозной путь при полном нажатии ~v²/2200 px);
* **интегратор** внутреннего ПИДа сам находит равновесие «сколько держать, чтобы зона
  стояла», а **измеритель равновесия** (`hover_adapt`) измеряет его напрямую из ускорения
  зоны за два окна по 0.5 с и подтягивает bias (в журнал пишется `⚖ Точка равновесия`).
  Если у твоего клиента равновесие сильно отличается от 0.5 — впиши измеренное в `pid_bias`;
* **свободная полоса** `zone_margin` (px): пока рыба внутри зоны с запасом — регулятор молчит;
* защиты из 1.4.0 остались: ШИМ-окно растягивается под реальные кадры (но ≤150 мс),
  «полка»/«дно» принудительно отпускают/держат, выход из аварии — с гистерезисом.

* **ШИМ-окно подстраивается под реальные кадры.** Период ШИМ = `1/pwm_hz`, но никогда не
  короче ~2.5 шагов цикла (и не длиннее 150 мс). Иначе на 20 к/с решение всегда
  принималось в начале окна и любое `duty > 0` означало «держать бессрочно».
* **«Полка»/«дно».** Если зона упёрлась в верх шкалы, а рыба под ней — удержание физически
  бесполезно (выше некуда), и регулятор принудительно отдаёт `duty = 0`, чтобы зона
  опустилась на рыбу. Симметрично у нижнего края («дно»): `duty = 1`. Аварийный режим (красная рамка) при
  этом тоже не «перебивает» кламп, а выход из аварии идёт с гистерезисом в несколько кадров,
  чтобы моргающий контур не бросал регулятор между нормой и аварийными коэффициентами.
Ошибка нормирована высотой шкалы: `err = (центр зоны − позиция рыбы) / высота_шкалы`,
`+` = зона ниже рыбы (надо поднимать ⇒ держать ЛКМ). Выход — скважность `duty` ∈ [0..1]:

```
duty = clamp(bias + Kp·e + Ki·∫e·dt + Kd·de/dt, 0, 1)
```

**Порядок настройки (5 минут; обычно ничего крутить не нужно — дефолты прогнаны по
модели физики мини-игры):**
1. Включи «Только мини-игра» (`auto_cast` = выкл) и встань на клёв руками.
2. **`pid_bias`** — стартовая оценка равновесия. Не подбирай руками: с `hover_adapt` (вкл)
   бот сам измерит его за ~1 с и напишет в журнал `⚖ Точка равновесия зоны: 0.27 …`.
   Если хочешь без подстройки — впиши измеренное число в `pid_bias`.
3. **`vel_gain`** (5.0, 1/с) — как агрессивно зона догоняет рыбу. Медленно догоняет → ↑.
   Дёргается → ↓.
4. **`stop_acc`** (500 px/с²) — запас на торможение. Проскакивает рыбу → ↓; вяло
   подъезжает → ↑.
5. **`Kp`** (1.8) / **`Ki`** (1.4) / **`Kd`** (0.10) — теперь это ПИД по СКОРОСТНОЙ ошибке:
   Kp давит перегон, Ki добирает остаток, Kd гасит рывки. Раскачка после разворота рыбы → ↓Kp/↓Ki.
6. **`pwm_hz`** (45 Гц) — частота ШИМ-цикла. Меньше (25–35) → меньше событий мыши;
   больше (60–120) → плавнее. Оптимум обычно 35–60.
7. **`zone_margin`** (18 px) — свободная полоса внутри зоны. Рыба на краю зоны дёргается → ↑.
8. **Упреждение** `lead_time` (0.075 с) и `lead_max` (38 px) — заброс точки цели по
   скорости/ускорению рыбы. Рыба «опережается» — увеличь `lead_time`.
9. **Аварийный режим** `pid_em_kp/ki/kd/bias` — по красной рамке срыва: догоняет рыбу с
   учётом инерции (если зона уже летит к рыбе — не разгоняет её дальше). Не догоняет → ↑`pid_em_kp`.
10. Мелочь: `max_hold`, `lost_ms`, `fish_timeout`, `fish_thr`, `slip_thr` — как в 1.4.0.

**Симптомы → что крутить**

| Симптом | Делай |
|---|---|
| зона дёргается/гудит вокруг рыбы | ↓ `Kp`, ↑ `zone_margin` |
| зона не успевает за рыбой, «догоняет» сзади | ↑ `vel_gain`, ↑ `lead_time`, ↑ `pwm_hz` |
| проскакивает рыбу (перелёт) | ↓ `stop_acc`, ↓ `Kp` |
| зона сползает, когда рыба по центру | проверь `⚖ Точка равновесия` в журнале → впиши в `pid_bias` (или держи `hover_adapt` вкл) |
| рыба срывается в последние секунды | ↑ `pid_em_kp`, ↑ `pid_em_bias` |
| «рыба не видна» (потеря) при яркой воде | ↓ `fish_thr`, либо `fish_detect = both` |
| ложный «срыв» | ↑ `slip_thr`, ↑ `bar_pad`, если рамка шире/у́же |
| бот «не видит» мини-игру после смены разрешения | ничего: `bar_autofit` сам поправит `bar`; проверь журнал `📐 Шкала уехала` |

Для точной ручной подстройки значения можно править прямо в `fishmod_config.json`
(перезапуск не нужен: конфиг перечитывается кнопкой «Загрузить»).

## 8. Язык интерфейса: RU / EN / UA

* Переключение — страница **«Настройки» → «RU / EN / UA»**: язык меняется **мгновенно**,
  без перезапуска (перерисовывается текущая страница, обновляются статус, пилюля-оверлей,
  журнал и будущие уведомления). Выбор сохраняется в `fishmod_config.json` (`"lang"`).
* Все строки живут в одном словаре `STRINGS` в начале `eternal_fishmod.py`
  (раздел «1B. ЛОКАЛИЗАЦИЯ»), доступ — через `t("ключ", ...)`.
* **Как поправить формулировку / добавить язык:** найди `STRINGS = {` и правь строки в блоке
  `"ru" | "en" | "ua"`. Ключи во всех языках должны совпадать; при пропуске берётся
  русская строка, а если нет и её — выводится сам ключ (так легко заметить дырку).
  Динамика подставляется через `{}`: `"log_caught": "🐟 Поймано #{n} (мини-игра {dur:.1f} с)"`.
  Внутренние идентификаторы (ключи конфига, имена шаблонов, хоткеи, `kind` состояний)
  **не переводятся** — только то, что видит пользователь.
* Сообщения лаунчера (`launch.py`) переводятся отдельно, словарём `LS`; язык берётся из
  конфига (или флага `--lang`).

## 11. Версионирование и релизы (процесс на будущее)

Правило: **любое осмысленное изменение кода заканчивается выпуском версии.** Одна команда
делает бамп версии, запись в CHANGELOG, коммит, тег и GitHub Release с архивом.

```bash
# ОДНОРАЗОВО: настройка GitHub CLI
winget install GitHub.cli          # или https://cli.github.com
gh auth login                      # браузерный вход; для этого репо хватит repo-скоупа
gh repo set-default marlen71/AutoFish

# КАЖДЫЙ РАЗ после правок:
python scripts/release.py patch    # багфикс/подкрутка параметров   1.3.0 -> 1.3.1
python scripts/release.py minor    # новая фича (страница, метод)   1.3.0 -> 1.4.0
python scripts/release.py major    # ломающие изменения (формат конфига) 1.3.0 -> 2.0.0
python scripts/release.py patch --notes "ПИД: дефолтный Kp 2.6 -> 3.0"   # сразу с текстом релиза
python scripts/release.py minor --dry-run      # посмотреть план, ничего не меняя
python scripts/release.py minor --no-push      # только локальный коммит+тег
python scripts/release.py --publish-only       # релиз для текущей версии (если пуш/релиз упал)
```

Что делает `scripts/release.py`:
`VERSION` → бамп по semver → та же версия в `APP_VERSION` внутри `eternal_fishmod.py` →
новая дата-запись в начало `CHANGELOG.md` → `git add -A && git commit -m "release: vX.Y.Z"` →
`git tag -a vX.Y.Z` → `git push && git push origin vX.Y.Z` → `gh release create vX.Y.Z`
с прикреплённым `eternal_fishmod_vX.Y.Z.zip`. **В архиве — только то, чем пользуются:**
`eternal_fishmod.py`, `launch.py`, `start.bat`, `start_admin.bat`, `start.vbs`,
`requirements.txt`, `README.md`, `VERSION` и `templates/` (откалиброванные шаблоны).
Распаковал → двойной клик → работает. Тесты, `scripts/release.py`, `.github/`, `CHANGELOG.md`
и прочее остаются в репозитории как исходники (состав списка — `INCLUDE_FILES`/`INCLUDE_DIRS`
в `scripts/release.py`, его сторожит `tests/test_launcher_files.py`).

Если `gh` нет/не авторизован — скрипт попытается воспользоваться **REST API** по переменной
окружения `GITHUB_TOKEN` (Personal access token со scope `repo`), а если и её нет —
остановится на коммите и теге и напечатает готовую команду для публикации. Все ошибки
выводятся по-человечески (нет git / нет сети / тег уже существует / защищённая ветка и т.п.),
без «сырых» трейсбеков.

**Автоматический путь (GitHub Actions).** Пуш тега `v*.*.*` сам запускает
`.github/workflows/release.yml`: он проверяет синтаксис, собирает тот же архив, берёт
описание из `CHANGELOG.md` и создаёт/обновляет релиз. Отдельные credentials **не нужны** —
хватает встроенного `secrets.GITHUB_TOKEN` (в workflow прописано `permissions: contents: write`).
Релиз можно пересоздать вручную: Actions → *Release build* → Run workflow → указать тег.

Прикрепление архива проверяется, а не предполагается: и `release.py`, и workflow после
загрузки смотрят реальный список ассетов релиза (загрузка идёт на отдельный хост
`uploads.github.com`, который умеет обрываться; `release.py` поэтому делает до 3 повторов).
Если архив всё же не прикрепился — скрипт печатает готовую команду `gh release upload ...`;
до тех пор скачивай `Source code (zip)` со страницы релиза: в теге лежит ровно тот же набор
файлов, что и в архиве (`eternal_fishmod.py`, `launch.py`, `start*.bat`, `requirements.txt`,
`templates/`) — его также можно распаковать и запускать.

Где смотреть: **Releases** страницы репозитория — архивы и описания; [`CHANGELOG.md`](CHANGELOG.md) —
история; версия — в шапке окна бота, в пилюле-оверле, в заголовке лаунчера и в `fishmod.log`.

## 12. Не работает — что смотреть

| Симптом | Причина / решение |
|---|---|
| «удочка не найдена в инвентарь» | сбит шаблон `rod.png` → пересними (страница «Зрение»), либо задай `rod_click_pos` кнопкой 📍; проверь, что активно окно игры |
| клики есть, игра их игнорирует | запусти от администратора (`start_admin.bat`); проверь, что игра не в режиме «полный экран, исключительный режим» (лучше «окно без рамки») |
| чёрный/старый кадр на «Зрении» | RDP/виртуалка без DXGI — бот сам перейдёт на резерв **GDI** (строка `⚠ Весь захват перешёл на GDI`); скорость будет чуть ниже |
| «не удалось определить окно игры» | нажми F8, когда фокус в окне игры |
| FPS потока сильно ниже `capture_fps` | у монитора меньше герцовки или игра не перерисовывает кадр — снизь `capture_fps` (например 90) |
| бот «тупо зажимает ЛКМ», зона улетает наверх и не возвращается | проверь на «Зрении», какой бэкенд и сколько fps (медленный захват ломает ШИМ); проверь, что шкала в превью та самая (зелёная рамка облегает зону) — при переезде шкалы бот пишет `📐 Шкала уехала` и правит `bar` сам; каскадный регулятор 1.5.0 тормозит заранее и не даёт зоне «зависать» на полке |
| в конфиге `"capture_backend": "mss"` (из версии 1.2–1.3) | ничего делать не нужно: при загрузке значение мигрирует на `auto`, в журнале будет `⚙ Конфиг: значение "capture_backend": "mss" устарело` |
| «ни один бэкенд захвата не запустился» | нет/сломан DXGI-захват: `python -m pip install -U dxcam bettercam` и перезапуск; в RDP/VM или при защищённом окне бот сам возьмёт GDI-резерв, а чтобы работать строго по DXGI — `"capture_backend": "dxcam"` в `fishmod_config.json` |
| зона срывается в конце | ↑ `pid_em_kp`/`pid_em_bias`; проверь, что `bar_pad` покрывает красную рамку (иначе аварийный режим не включается) |
| ловит «пустоту»/ложные клики | подними `THR["rod"]`/`THR["bait"]`, пересними шаблоны на этом разрешении |
| после закрытия бота второй запуск «не видит» экран | освобождай DXGI корректно — закрывай окно кнопкой «×» или `F10`; при падении это делает `atexit` |
| `start.bat`: «... is not recognized as an internal or external command», код **9009** | в `.bat`/`.vbs` попала кириллица или файл стал с LF-переводами → восстанови оригиналы (`git checkout -- start.bat start_admin.bat start.vbs`) и не редактируй их в UTF-8/LF, см. §3.4 |
| нужен другой язык, но строк не хватает | добавь ключи в `STRINGS` (см. §8) — UI подхватит без перезапуска |

```bash
python tests/test_capture_backends.py # бэкенды захвата на подставных dxcam/bettercam/GDI:
                                 # API 0.0.x и 0.3.x, region-поток, отбраковка чёрного кадра,
                                 # причины отказа в тексте ошибки, GDI-резерв и деградация
                                 # в полёте, старый резервный пакет вырезан
```
Проверяет на реальных скриншотах: поиск зоны/рыбы/срыва, совпадение шаблонов, клик по пункту
«Использовать», работу каскадного регулятора (замкнутый контур на модели физики мини-игры
с инерцией: «ЛКМ = ускорение зоны», профиль подхода, равновесие, полка, 20 к/с), автокалибровку
шкалы (`scale_rect`/`autofit_bar`), полноту словарей `ru/en/ua` (включая совпадение `{}`-полей),
миграцию конфига и согласованность `VERSION`/`APP_VERSION`. Windows и запущенная игра не нужны; нужны только
`numpy` + `opencv-python`.
`test_launcher_files.py` не требует вообще ничего, кроме стандартной библиотеки — он про байты
файлов запуска. Тесты лежат в репозитории и в релизный архив не входят (первые три опираются
на скриншоты из корня репо) — для них нужен `git clone`, а не распаковка релиза.

## 14. Лицензия и ответственность

Скрипт сделан для игры «за тебя» на приватном RP-сервере и может нарушать его правила —
используешь на свой риск (рекомендуем разумные паузы и ограничение `bite_timeout`).
Помни, что античиты некоторых серверов реагируют на синтетический ввод.

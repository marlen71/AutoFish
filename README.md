# Eternal FishMod · Skyrim RP

Полуавтомат рыбалки для **Windows / Python 3.10+**. Пользователь выбирает место, калибрует элементы интерфейса, возвращается в игру; бот открывает инвентарь, использует удочку, ждёт появления шкалы, удерживает рыбу в зелёной зоне и повторяет цикл. Для мыши используется Win32 **SendInput**; клавиатура — pydirectinput. Игра должна разрешать автоматизацию; проверьте правила сервера.

## Установка и запуск

```powershell
py -3 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python eternal_fishmod.py
```

Эквивалент: `pip install opencv-python numpy mss pydirectinput keyboard`. Tkinter поставляется с обычным Windows Python, `ctypes`/`winsound` входят в стандартную библиотеку. Если игра запущена с правами администратора, программу тоже нужно запускать с теми же правами. На Linux бот **не запускается**: `vision.py` и тесты можно проверять офлайн. Тесты: `pip install pytest` и `python -m pytest tests`.

Файлы: `eternal_fishmod.py` — существующий Canvas GUI, конфиг, звук, журнал, SendInput, инвентарь, фоновый поток и цикл; `vision.py` — чистые тестируемые детекторы; `templates/` — PNG-шаблоны; `sounds/` — генерируемые WAV; `tests/` — синтетические и предоставленные кадры. `fishmod_config.json`, `fishmod_stats.json`, `fishmod.log`, `debug_*.png` создаются рядом со скриптом автоматически и не добавляются в Git.

### Первый запуск — обязательно проверить перед автоматическим циклом

1. Запустите в оконном или безрамочном режиме на **основном мониторе**. Базовая система координат — 1920×1080, `mss` масштабирует её к реальному размеру основного монитора. Предустановленные области соответствуют предоставленным снимкам. Сначала откройте инвентарь вручную и проверьте на вкладке **Зрение**, что `inv_header.png` зелёный. Шаблон заголовка получен из предоставленного снимка. Если UI масштабируется иначе — наведите курсор на заголовок, снимите новый шаблон через кнопку захвата (или подмените PNG вручную) и проверьте результат. Жёлтая/красная точка означает, что шаблон не совпал.
2. На **Настройки** задайте `ПКМ удочка` (центр первого слота; исходно 125,260) и `ЛКМ «Использовать»` (центр **верхнего серого** пункта; исходно 205,279). Поля и кнопка 📍 работают в координатах 1920×1080. **Никогда не указывайте красную нижнюю строку «Выбросить»**. Защита проверяет, что `Использовать` выше обнаруженной красной строки. Можно очистить координату «Использовать»: тогда бот вычислит точку над центром красной строки по `menu_up`. В режиме шаблона удочки снимите `rod.png` (кнопка на «Зрение»; есть задержка 4 секунды) и проверьте индикатор в открытом инвентаре. По умолчанию выбран более надёжный **фиксированный слот**. Если инвентарь отличается, выделите `menu_roi` в расширенных настройках: в прямоугольник должна целиком попадать красная нижняя строка. При нераспознанном меню бот останавливается, **не кликая** по неизвестной точке.
3. На сервере начните мини-игру вручную, остановите/не запускайте бота. В **Зрение** нажмите «Основная» и протяните прямоугольник только вокруг широкой синей полосы; «Прогресс» — внутри узкой светлой полосы без чёрной обводки (особенно важно захватить низ белого заполнения); «Тревога» — вокруг красного текста/таймера. Для сохранения фона можно выбрать цвет синей области пипеткой. `Esc` отменяет выделение. Выбранные прямоугольники сохраняются в базовом разрешении.
4. Пипеткой соберите **несколько** образцов зелёной зоны (вверху/внизу) и синего фона (светлые/тёмные сегменты). Образцы сохраняются как HSV, диапазон рассчитывается с допуском `sample_tolerance`, включая переход hue 179→0. Для рыбы рекомендован режим **«маска»**: насыщенные пиксели спрайта, которые не принадлежат ни синему фону, ни зелёной зоне. Если на вашем UI детекция плохая, наберите несколько цветовых образцов спрайта и переключите кнопку «Рыба: маска/образцы» в режим `samples`. Красный образец можно снять с предупреждения или нижнего пункта меню. Диапазоны и образцы доступны также в JSON/редакторе **Пороги / ROI / HSV**.
5. На странице **Зрение** проверьте живое превью: зелёная рамка зоны, оранжевая линия рыбы, узкая полоса, проценты заполнения и флаг тревоги. F9 сохраняет полный кадр, объединённое превью и две маски (`debug_*.png`); сравните их с реальным изображением. Убедитесь, что в режиме ожидания клёва зелёная зона **не** распознаётся. Настройте `zone_width_ratio`, `min_zone_area`, `fish_min_s`, `fish_min_v`, `fish_row_diff`, `min_fish_area`, `progress_row_ratio`, `progress_bottom_trim` и `warning_red_ratio` в редакторе, если нужно. Наживка по умолчанию **не проверяется**, потому что сервер может её не расходовать. Если нужен контроль — снимите `bait.png` с нужного предмета при открытом инвентаре и включите тумблер «Контроль наживки». Шаблон этого предмета будет искаться по сетке/скроллу.
6. На вкладке **Модули** проверьте режим заброса. По умолчанию **инвентарь каждый раз**: TAB → проверка наживки (если включена) → ПКМ удочка → верхнее «Использовать» (это и есть заброс) → ожидание мини-игры. Альтернатива **удочка в руках**: зажатие/отпускание ЛКМ для заброса, проверка наживки раз в N забросов. Переключать режим только при остановленном боте. Нажмите F8 в игре либо «СТАРТ» в GUI и в течение 15 секунд вернитесь в окно игры. По умолчанию в заголовке активного окна должно быть слово `Skyrim`; при другом заголовке укажите `game_title_hint` в «Пороги / ROI / HSV».

### Хоткеи и безопасность

| Клавиша | Действие |
|---|---|
| F8 | Старт/стоп (toggle) |
| F10 | Аварийный стоп + отпускание мыши и клавиш |
| Insert | Показать/скрыть GUI |
| F9 | Диагностический снимок и маски |

Все четыре клавиши переназначаются на вкладке «Настройки»; Esc отменяет запись новой клавиши. Отправка новых нажатий идёт только при фокусе обнаруженного игрового окна; потеря фокуса освобождает кнопки и ставит поток на паузу. После возврата управление продолжается. Stop/Event и `try/finally` гарантируют попытку отправить UP при остановке/ошибке, но при блокировке SendInput самой игрой не существует программной гарантии её внутреннего состояния: **проверьте мышь вручную при аварии**. Программа не кликает вслепую при нераспознанном меню.

Ограничения по времени: `bite_timeout`, `no_bite_limit`, `minigame_timeout`, `max_lost_games`, `max_failures`, `menu_timeout`, `warning_seconds` и другие параметры настраиваются через **Зрение → Пороги / ROI / HSV**. В статистике отдельно сохраняются подтверждённые уловы, срывы и **неясные исходы**; исчезновение шкалы без подтверждения заполнения **не засчитывается автоматически как улов**. Тревога обнаруживается по красному цвету и/или опциональному `warning.png`, без OCR: показанное «≈ N с» — локальная **оценка от первого обнаруженного кадра**, не считывание цифр игры. Подберите `warning_seconds` по реальному таймеру. После потери контакта с рыбой/мини-игры неопределённые исходы приводят к автостопу после `max_lost_games` случаев.

## Известные ограничения / предположения

- По предоставленным кадрам нельзя доказать, что шкала всегда исчезает только при успехе. Улов подтверждается заполненной узкой полосой в двух последовательных кадрах; если игра скрывает шкалу слишком быстро, результат будет `unknown`. Посмотрите F9/лог, при необходимости настройте `progress_full` и `progress_full_frames` (уменьшайте осторожно).
- Красная рамка пульсирует, поэтому предупреждение держится между кадрами до восстановления; отображаемый таймер приблизителен. Если исчезновение шкалы произошло при активной тревоге, фиксируется срыв. При изменении текста снимите `warning.png` и/или обновите красную HSV-маску.
- Синяя полоса и спрайт бывают разными. При ложной рыбе обновите выбор `bar`, уменьшите ширину ROI до **внутренней** полосы, возьмите больше образцов синего, попробуйте `samples`. При ложном 100% прогресса проверьте, что ROI не включает белые заголовки/рамку, и поднимите `progress_row_ratio`.
- Шаблоны нужно заново снять после изменения UI-scale сервера, масштаба Windows, шрифта или вида наживки. Скролл инвентаря может отличаться на другой сборке — включайте контроль наживки только после проверки шаблона. Для `rod_mode=template` координата удочки из template уже физическая; фиксированная координата — базовая.
- Точные задержки игры, анимация переключения меню и скорость зоны не могут быть протестированы без запущенного Skyrim RP под Windows. Проверьте первый цикл **под наблюдением**, с F10 под рукой. Редактор поддерживает все численные пороги и ROI без редактирования кода; модуль `vision.py` проверен автоматическими тестами на переданных кадрах.
- `monitor()` выбирает основной монитор. Переместите игру на него; на нескольких мониторах виртуальный рабочий стол учитывается SendInput, но детекция захватывает именно основной. Не используйте поверх игры другие оверлеи, которые совпадают по цвету с целевой шкалой.

### Источник и архитектура

Сохранены исходные Canvas-отрисовка без Pillow, пять вкладок, тосты, статус-плашка, конфиг/статистика, WAV-синтез, логирование, шаблоны, `mss`, `SendInput`, горячие клавиши и поток исполнения. Переписаны распознавание шкалы, прогресса и тревоги, выбор режима заброса и учёт результата. Для toggle и безопасной остановки использован тот же подход разделения регистрации хоткеев и цикла исполнения, что в [oriash93/AutoClicker](https://github.com/oriash93/AutoClicker) (там WPF/C# с таймером, здесь Python с `threading.Event` и `try/finally`; код напрямую не копировался).

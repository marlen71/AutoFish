# Assist (Windows)

Точка входа: `Assist.py` в корне репозитория. `screen_assist/` содержит внутренние
модули Assist. Это самостоятельная программа, не часть рыбалки.

Отдельный экспериментальный инструмент, скрипт рыбалки не изменяет. Берёт только
пиксели выбранного монитора: не читает память игры и не показывает скрытые за
стеной объекты. Детектор может ошибаться и находить частично перекрытые фигуры;
это не проверка игровой видимости по геометрии мира. Используйте только там,
где автоматизация разрешена, например в своём офлайн-тесте. Обхода античита нет.

## НейроАссист: сбор → разметка → обучение

1. «Сбор кадров и предложений боксов»: F8 начинает/приостанавливает запись, F10
   возвращает окно. Первые две секунды после старта отведены на возврат в игру.
   В оперативной памяти держатся три JPEG с частотой около 4 Гц; при нажатии ЛКМ
   они сохраняются вместе с кадрами следующих 0.75 секунды. Фон сохраняется
   раз в 2 секунды. ЛКМ опрашивается, очень быстрые клики могут пропускаться.
   Метки ЛКМ/ПКМ, курсор и **предполагаемый** центр прицела записываются в session.json.
   Это не определение попаданий/цели и не запись игровых команд движения.
2. «Проверить и разметить кадры»: выберите папку сессии. Протяните мышью
   прямоугольники вокруг ВСЕХ видимых персонажей, выбирая класс «Другой игрок»
   или «Свой персонаж». Зелёный = другой, красный = свой. «Подтвердить и дальше»
   сохраняет разметку, в том числе пустой кадр. «Пропустить» не подтверждает его.
   При включённой предразметке боксы уже предложены моделью. ПКМ внутри бокса
   удаляет его; можно очистить все и нарисовать заново. Обязательно исправьте своего
   игрока: стандартная YOLO не отличает его от остальных. Нажатие подтверждения
   означает проверку ВСЕГО кадра. Пропуск не разрешает обучение на нём.
3. «Дообучить отдельную модель»: выберите ту же папку. Нужно минимум 30
   проверенных кадров, рекомендуются сотни разнообразных примеров. Обучение
   запускается отдельным процессом на 20 эпох, скачивает начальную yolo11n.pt.
   Сначала закройте игру. CPU работает медленно, GPU включайте только после
   установки совместимого с вашей картой PyTorch/CUDA. BAT устанавливает CPU-сборку;
   галочка GPU сама CUDA не устанавливает. Для GTX 1080 Ti совместимость не проверена.
4. Результат: `Assist_training/<запуск>/candidate/weights/best.pt`, логи
   `Assist_training/train_*.log`. Выберите best.pt в главном окне вручную,
   классы оставьте **0**: класс 1 (свой) не выводится и не выбирается целью.
   Распознавание своего основано на картинке, не гарантирует исключение при смене
   скина/камеры. Различения союзников нет.

Обучение использует только подтверждённые кадры. Последняя часть сессии выделяется
для проверки, три кадра на границе пропускаются, чтобы уменьшить пересечение серий.
Это всё ещё одна сессия: обязательно испытайте кандидата на другой игровой сессии.
Автоактивации и автоматического решения «модель стала лучше» нет. Старые модели
не перезаписываются. Закрытие главного окна не отменяет дочернее обучение;
при необходимости завершите его процесс Python через диспетчер задач.

Всё остаётся локально в `Assist_captures/` и `Assist_training/`.
Записывается ВЕСЬ монитор (чат и личные окна тоже), не только игра. Ставьте
паузу перед переключением окон. Максимум 500 кадров; точные последовательные
и близкие по уменьшенному изображению повторы среди последних 20 кадров
пропускаются. Небольшие изменения/далёкие персонажи могут отфильтроваться ошибочно. Кнопка сохранения ZIP упаковывает кадры и метаданные.
Перед передачей проверяйте личные данные. Ничего автоматически не отправляется.
Архив может содержать файл ручной разметки, если он уже создан в папке.

### Фоновая предразметка и очередь исправлений

Галочка в главном меню включает отдельный поток предсказаний для сохранённых
кадров. Используется выбранная модель и поле классов; при пустом поле модели
скачивается `yolo11n.pt` (нужен интернет), для неё оставляйте класс 0.
CPU-предразметка ограничена двумя потоками PyTorch. Частота зависит от компьютера,
это не гарантия обработки каждого кадра за время его захвата и не живой оверлей.
Очередь ограничена восемью заданиями; если она заполнена, кадр остаётся на диске
без предложений и доступен для ручной разметки. Ошибка модели/скачивания не
останавливает запись. Статус, очередь и число пропущенных предложений видны
в окне сбора. Предразметку можно отключить до начала новой сессии.

Предложения пишутся атомарно в `suggestions/*.json` отдельно от `annotations.json`.
Они ВСЕГДА непроверенные, даже при высокой уверенности. Просмотр сначала показывает
непроверенные кадры без детекций/без предложений и кадры с низкой уверенностью.
Это эвристика очереди, а не доказательство ошибки модели; проверяйте и уверенные
кадры. При повторном открытии уже подтверждённая ручная разметка имеет приоритет.
Обучение не читает `suggestions/` вообще.

После F10 дождитесь нулевой очереди перед экспортом ZIP. Закрытие окна сбора
отменяет ожидающие задания, текущее может завершиться позже. Уже сохранённые
кадры и предложения остаются. Начальная модель обучена на фотографиях, поэтому
качество на игре может быть низким. Обучения на лету и автоматической замены
весов во время игры нет: предсказание не равно достоверной разметке.

## Простой запуск через BAT (без сборки)

Распакуйте **весь** Assist.zip в отдельную папку и дважды нажмите
`Start_Assist.bat`. Нужен установленный Python 3.11 или 3.12 (64-bit).
При первом запуске BAT создаст `.assist-venv`, скачает зависимости (включая
CPU PyTorch; нужен интернет и несколько ГБ места), затем откроет меню Assist.
Повторный запуск не переустанавливает пакеты. При ошибке окно останется открытым.
Модель `.pt` нужно выбрать самостоятельно: она не включена в архив.

## Приложение Windows (.exe)

GitHub → Actions → **Build Assist for Windows** → последний успешный запуск →
Artifacts → **Assist-Windows-x64**. Для скачивания артефакта войдите в GitHub.
Распакуйте весь архив и запустите `Assist.exe`. Папку `_internal` рядом с exe
нельзя удалять: в ней зависимости. Установка Python не требуется.
В окне выберите свою модель `.pt`, настройте FOV и плавность, нажмите «Запустить Assist».
Сборка не включает веса. При двойном щелчке по `Assist.py` также открывается окно,
но для Python-версии зависимости нужно установить самостоятельно.
Лог exe: `%LOCALAPPDATA%\Assist\assist.log`.

## Установка и запуск

Windows 10 версии 2004+ / Windows 11, Python 3.10+, оконный или безрамочный режим.
Из корня репозитория:

```powershell
py -m pip install -r screen_assist/requirements.txt
py Assist.py --model C:\models\players.pt --classes 0 --fov 100 --smooth 10
```

**Веса players.pt в репозитории отсутствуют.** Нужна совместимая YOLO detection
модель с классом игрового персонажа. `--classes` задаёт индексы классов именно
вашей модели. В COCO класс person имеет индекс 0, но обычная COCO-модель может
плохо работать с показанными игровыми скинами. Скриншоты сами по себе не являются
обученным детектором. Для надёжной работы нужен размеченный набор кадров из игры
с разными скинами, позами, расстояниями и фоном, обучение и отдельная проверочная
выборка. Загружайте веса только из доверенных источников.

## Управление

По умолчанию выключен. **F8** — включить боксы и помощь; **F10** — выход.
**F6** — голова / туловище. Удерживайте **ПКМ**: доводка происходит только если
точка цели внутри круглого FOV вокруг центра экрана. Боксы вне круга остаются.
Ближайшая к центру точка выбирается заново на каждом кадре (фиксации ID нет).
При отпускании ПКМ или потере детекции движение прекращается.

- `+` / `-` (основная клавиатура) — smooth: больше означает медленнее.
- `[` / `]` — радиус FOV в физических пикселях (коды клавиш OEM).
- `--origin cursor` — вместо центра экрана использовать положение курсора.
- `--speed 900` — максимальная скорость относительного движения.
- `--monitor 1` — номер монитора MSS, начиная с 1.
- `--confidence .55` — порог уверенности.
- `--head-ratio .13 --body-ratio .42` — высота точки внутри бокса от верхнего края.

Настройки во время работы не сохраняются; постоянные значения задавайте аргументами.
Голова/туловище — **приближённые точки по пропорциям бокса**, не распознавание
костей. На присевшем или перекрытом персонаже возможна ошибка. Собственный
персонаж от третьего лица тоже может детектироваться: распознавания команд и
исключения своего игрока здесь нет.

Оверлей прозрачный для кликов и исключается из захвата Windows; если исключение
недоступно, запуск прекращается во избежание обратной связи. Эксклюзивный полноэкранный
режим не поддерживается. Игры с raw input могут игнорировать mouse_event;
чувствительность игры влияет на доводку, пиксели экрана не равны углам камеры.
Медленная модель ухудшает отзывчивость: F10 обрабатывается между вызовами inference,
а не внутри зависшего драйвера. Перед проверкой в игре испытайте на статичном изображении.

## Проверка

```sh
python -m unittest screen_assist.test_core screen_assist.test_train screen_assist.test_proposals -v
```

Тесты проверяют только геометрию, радиус выбора и плавность. Захват, Windows-оверлей,
модель и управление мышью требуют ручной проверки на целевом компьютере.

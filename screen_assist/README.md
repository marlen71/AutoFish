# Assist / НейроАссист — Windows

Самостоятельная программа: экранный детектор, боксы, помощь в наведении и локальные
инструменты подготовки модели. Рыбалку не использует и не изменяет. Только захват
монитора, без чтения памяти, координат мира и обхода античита. Используйте только
в своей тестовой среде или там, где автоматизация разрешена.

## Запуск и обновление

Windows 10 2004+ / Windows 11, оконный/безрамочный режим игры, Python 3.11/3.12 x64.
Распакуйте **весь** Assist.zip и запустите `Start_Assist.bat`. Первый запуск создаёт
`.assist-venv` и скачивает CPU PyTorch и остальные зависимости. Нужен интернет и
несколько ГБ места. Повторная установка не требуется. Ошибки остаются в окне BAT.

При обновлении закройте Assist и замените файлы программы. Не удаляйте свои
`Assist_captures/`, `Assist_training/` и окружение. Настройки сохраняются рядом с
программой в `assist_settings.json`. Чтобы вернуть значения по умолчанию, закройте
Assist и переименуйте этот файл. Не запускайте несколько копий одновременно.

В архиве есть загруженная пользователем **game_detector_final.pt**. Метаданные:
класс **0 player**, **1 self**. Оставляйте класс 0: self/own_player дополнительно
отфильтровываются из ESP/наведения. Это не гарантия распознавания своего: модель
может перепутать классы при смене скина/камеры. Команды не различаются. Вторая
модель `game_detector.pt` в репозитории имеет один класс 0 person.
Весам не проводилась полноценная независимая оценка качества. Загружайте .pt
только из доверенных источников: формат может содержать исполняемую сериализацию.

## Новое меню

Тёмно-серое меню с красными акцентами, отдельное от FishMod:

- **Наведение:** включение помощи, `rmb` (только ПКМ) / `auto` (без ПКМ),
  `head` / `body`, FOV, smooth, скорость и максимальный возраст детекции.
- **ESP:** боксы по всему монитору, круг FOV, удержание боксов, ограниченная
  компенсация движения, необязательный фильтр координат (по умолчанию 0).
- **Триггер:** включение, радиус допуска, задержка перед кликом и интервал.
- **Детектор:** модель, классы, монитор, устройство, размер входа, два порога
  уверенности, число потоков CPU и профили «Быстро», «Баланс», «Мелкие цели».
- **Данные:** сбор кадров, предварительная разметка, ручная проверка и обучение.

Нажмите «Запустить Assist», затем вернитесь в игру и нажмите **F8** именно в её
окне. Это привязывает автоматический ввод к текущему окну. При переключении на
рабочий стол/другое приложение движение и клики приостанавливаются. F8 — общий
старт/стоп, **F10 — аварийный выход**. Все старые треки сбрасываются при F8.

**Insert** открывает/закрывает меню поверх работы. Пока оно открыто, ввод отключён.
«Применить и сохранить» меняет параметры наведения/ESP/триггера без перезапуска.
После закрытия вернитесь в окно игры. Модель, устройство, размер входа и пороги
детектора меняются после F10 и повторного запуска, в live-меню они недоступны.
Горячие изменения F6/F7/F9 сохраняются только при применении меню.

Горячие клавиши:
- **F6** — голова/туловище; **F7** — auto/ПКМ; **F9** — триггер вкл./выкл.
- **+ / −** основной клавиатуры — smooth (больше = медленнее).
- **[ / ]** — радиус захвата наведения, в физических пикселях.

Прицел по умолчанию предполагается в центре монитора. `cursor` использует положение
системного курсора, что подходит не всем играм. Голова и туловище — приблизительные
точки по пропорциям бокса (0.13 и 0.42 высоты), не распознанные игровые кости.

## Пропадания, задержка и дальние персонажи

Захват и YOLO работают в отдельном потоке. UI и ввод обслуживаются независимо,
примерно раз в 16 мс; это не гарантия 60 FPS нейросети. Очередь кадров не накапливается.
Перед записью первого результата выполняется прогрев модели. `auto` пробует доступный
CUDA GPU и при ошибке прогрева переходит на CPU. Это **не устанавливает CUDA**:
BAT содержит CPU PyTorch; совместимость GPU/драйвера GTX 1080 Ti здесь не проверена.
При выборе `0` тоже проверяется доступность CUDA: если GPU недоступен или прогрев
не проходит, Assist переходит на CPU и выводит предупреждение в оверлее.
Это предотвращает остановку, но не ускоряет работу на CPU и не исправляет драйвер.

Для GTX 1080 Ti приложен отдельный **Install_GPU_1080Ti.bat**. Сначала один раз
запустите обычный BAT, затем закройте Assist и обучение. GPU-BAT с подтверждением
устанавливает в то же окружение фиксированную сборку PyTorch 2.7.1 / torchvision
0.22.1 с CUDA 11.8 для старых Pascal-карт, а не последние GPU-колёса, которые могут
не содержать нужную архитектуру. Нужен Python 3.10..3.12 и подходящий драйвер NVIDIA;
скачивается несколько ГБ. Отдельный CUDA Toolkit не нужен. После установки BAT
проверяет не только наличие CUDA, но и реальную свёртку на GPU, печатает название
карты. Только после успешной проверки выбирайте auto/0. На этой машине Windows/GPU
не доступны, поэтому результат проверки на вашей карте заранее не гарантирован.
При ошибке сохраните текст; auto может работать на CPU с этой же сборкой.

Используются два порога: новый бокс создаётся при confidence >= 0.22, а уже известный
может продолжаться при >= 0.12. Это уменьшает мерцание слабых детекций, но не заменяет
обучение. Неподтверждённый кратковременно бокс показывается **приглушённым пунктиром**,
по умолчанию не дольше 350 мс от времени захвата. Это старый трек, не доказательство
текущей видимости. Его можно сократить во вкладке ESP.

Ограниченная экстраполяция движения по двум измерениям компенсирует до 60 мс
(настройка 0..100 мс), смещение ограничено долей размера бокса. Она не предсказывает
надёжно резкий поворот и может ошибаться; при перелётах установите 0.
Сглаживание бокса по умолчанию выключено. Наведение не использует детекции старше
200 мс (предел регулируется 30..300 мс); устаревшая позиция не становится свежей
за счёт экстраполяции. Треки сопоставляются по IoU, постоянные ID при пересечении
игроков не гарантированы.

**У ESP нет радиуса в метрах**: детектор получает весь выбранный монитор, независимо
от круга FOV. Дальность ограничивают число пикселей персонажа и качество весов.
Профиль «Мелкие цели» использует вход 960 и более низкие пороги; доступен также
1280. Это может помочь увидеть маленькую фигуру, но **сильно увеличить задержку
на CPU**. Для начала используйте 512 или профиль «Баланс» (640); если Inference
слишком велик — 416/320. Низкая уверенность добавляет ложные боксы.

В оверлее показаны `Inference` (время обработки) и `age` (возраст кадра).
`STALE` означает, что наведение остановлено из-за старых данных. Увеличение времени
удержания ESP не ускоряет нейросеть и не делает наведение точнее. Гарантировать
дальнее распознавание без проверки/обучения модели нельзя.

## Триггер

По умолчанию **выключен**. При общем F8 ON работает в режиме auto либо с зажатой
ПКМ согласно выбранному режиму. Наведение мыши можно отключить отдельно.
Для клика нужны:
- активное привязанное окно, закрытое меню;
- точка головы/туловища в заданном радиусе от прицела и прицел внутри бокса;
- подтверждение именно последним результатом, возраст не более min(120 мс, aim_age);
- непрерывная задержка на одной цели (по умолчанию 100 мс).

Генерируются короткие клики ЛКМ (около 25 мс, зависит от UI), интервал минимум 220 мс
по умолчанию. Ручное удержание ЛКМ не запускает дополнительный автоклик. Потеря цели,
смена окна, открытие меню, отключение и выход освобождают синтетически нажатую кнопку.
Триггер не знает о попадании, оружии, перезарядке или союзниках. Игры с raw input
могут не принимать mouse_event; обхода ограничений нет.

## Локальный датасет и обучение

1. Во вкладке **Данные** запустите сбор. **F8** — запись/пауза, **F10** — возврат
   к окну сбора (в этом режиме не закрывает приложение). Первые 2 секунды — на возврат
   в игру. До трёх JPEG хранятся в буфере с частотой около 4 Гц. При нажатии ЛКМ
   сохраняются кадры до и следующие 0.75 с; фон — раз в 2 с. Быстрые клики могут
   пропускаться. Максимум 500 кадров, похожие среди последних 20 пропускаются;
   небольшие изменения тоже могут отфильтроваться ошибочно.
2. Фоновая предразметка отдельным CPU-потоком предлагает боксы выбранной моделью.
   Пустое поле модели скачивает yolo11n.pt. Очередь ограничена 8 заданиями: при
   переполнении кадр остаётся без предложений. Ошибка модели не останавливает сбор.
   Всё сохраняется в `Assist_captures/<сессия>/`. Клики/курсор/предполагаемый центр
   прицела записываются в session.json, это не истинные цели и не подтверждение попаданий.
3. «Проверить и разметить»: выберите папку сессии. Просмотр начинает с непроверенных
   кадров без детекций и с низкой уверенностью (эвристика, не оценка качества).
   Проверьте ВСЕХ персонажей: зелёный — другой игрок, красный — свой. Протяните мышью
   новый бокс, ПКМ внутри бокса удаляет его, есть очистка и отмена последнего.
   «Подтвердить и дальше» сохраняет разметку, в том числе пустого кадра. «Пропустить»
   не подтверждает его. Кадры модели не становятся проверенными автоматически.
4. «Дообучить»: минимум 30 проверенных кадров, лучше сотни разнообразных.
   Запускаются 20 эпох отдельным процессом с начальными yolo11n.pt. Закройте игру.
   CPU может работать часами; GPU требует совместимого PyTorch/CUDA.
5. Кандидат: `Assist_training/<запуск>/candidate/weights/best.pt`, логи рядом
   `train_*.log`. Новая модель **не активируется автоматически**, старые не заменяются.
   Выберите best.pt во вкладке Детектор, класс 0. Закрытие главного меню не отменяет
   дочернее обучение: при необходимости завершите его Python-процесс вручную.

Обучение читает только подтверждённый `annotations.json`, НЕ `suggestions/*.json`.
Проверка выделяет последнюю часть сессии, с пропуском 3 кадров на границе.
Это не независимая выборка: отдельно испытайте кандидата на другой игровой сессии.

**Сбор захватывает ВЕСЬ монитор**, включая чат и личные окна. Пауза перед переключением
приложений обязательна. Автоматических загрузок данных нет. Перед экспортом ZIP
дождитесь нулевой очереди предразметки и проверьте личные данные. Закрытие сбора
отменяет ожидающие задания; текущее может завершиться позже. Уже сохранённые файлы
остаются на диске. Присылать виртуальное окружение и все гигабайты проекта не нужно.

## CLI, EXE и тесты

```powershell
py -m pip install -r screen_assist/requirements.txt
py Assist.py --model game_detector_final.pt --imgsz 512 --aim-activation rmb
py Assist.py --model game_detector_final.pt --aim-activation auto --trigger-enabled
python -m unittest discover -s . -p "test_*.py" -v
```

`py Assist.py --help` — все настройки. Голова/туловище: `--head-ratio`/`--body-ratio`.
EXE собирается в GitHub Actions → Build Assist for Windows → Artifacts →
Assist-Windows-x64 (нужен вход в GitHub). Распакуйте весь архив, `_internal`
удалять нельзя. Python для EXE не нужен. Лог: `%LOCALAPPDATA%\Assist\assist.log`.

Тесты проверяют математику, треки, пороги, компенсацию, триггер, настройки и подготовку
датасета. Windows-захват, интерфейс, реальный ввод, CUDA и качество весов требуют
ручной проверки на целевом компьютере. Совместимость с игрой не гарантируется.

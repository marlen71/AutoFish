# Assist — AI Workspace / Rebuild 2

Самостоятельное Windows-приложение с экранным AI: ESP по видимому изображению,
наведение, триггер, диагностика и локальный датасет. Не требует FiveM-ресурса,
изменений RMRP/сервера или доступа к памяти игры. Это не гарантия совместимости с
правилами/античитом игры: используйте в разрешённой тестовой среде. Рыбалка и
экспериментальный FiveM Lab в этой сборке не используются.

## Исправление улётов — 2.0.1

Исправлен цикл доводки: **один шаг только на новый результат детектора**, а не
многократное движение по одному старому измерению в каждом UI-кадре. Перед первым
движением нужны минимум два последовательных согласованных измерения одной цели.
Смена ID, резкий скачок размеров/центра бокса, потеря или старение детекции
приостанавливают доводку. Пунктирный ESP может оставаться, но не используется для
наведения. Это может уменьшить отзывчивость при очень низком FPS детектора.

Наведение и триггер используют **последний исходный бокс**, не прогнозируемый и
не сглаженный. Настройка prediction теперь относится только к визуальному ESP.
Точка ограничена внутренними 2..98% высоты реального бокса. Это всё ещё не игровые
хитбоксы: модель может неверно обвести персонажа или не знать его позу.

В разделе «Наведение» добавлены:
- gain 0.35 — коэффициент доводки;
- step limit 4 — максимум отсчётов относительного ввода за одну новую детекцию,
  не гарантированные пиксели/углы игры (чувствительность и ускорение влияют);
- deadzone 2 px — не дёргать прицел около точки;
- confirmations 2 — число согласованных кадров;
- crosshair X/Y — поправка к центру экрана; при выходе центра за монитор ввод выключен;
- head/body ratio — высота целевой точки в боксе от верхнего края.

Для калибровки сначала **выключите помощь и триггер**. В оверлее жёлтый крест должен
совпасть с игровым прицелом; поправьте X/Y, если они различаются. В диагностике без
ввода показаны крест и жёлтые точки модели. При активном выборе цели жёлтая линия
указывает фактическую точку доводки в исходном боксе. Head/body ratio корректирует
положение точки, но не заменяет отдельный детектор головы. Если чувствительность
игры высокая, начните с gain 0.15 и step limit 2. Не поднимайте одновременно gain,
лимит и скорость до максимума. Настройки старого конфига сохраняются, новые поля
получают безопасные значения по умолчанию.

## Обновление / запуск

1. Закройте старый Assist и обучение. Распакуйте весь новый `Assist.zip` с заменой
   файлов программы, либо в отдельную папку. Сохраните свои `Assist_captures/`,
   `Assist_training/`, веса и `assist_settings.json`.
2. Нужен Python **3.11/3.12 x64**, Windows 10 2004+ / Windows 11, оконный/безрамочный
   режим. Откройте **Start_Assist.bat**. При первом запуске Rebuild он обновит
   зависимости. Уже работающий GPU PyTorch не заменяется CPU-сборкой без необходимости.
3. Необязательные DXGI/ONNX-зависимости устанавливаются отдельно. Если этот шаг
   не удался, PyTorch/MSS остаются доступны. Лог: `assist_acceleration.log`.
   Повторная установка: **Install_Acceleration.bat**. DirectML не требует CUDA.
4. В новом меню с боковой навигацией откройте **Обзор → Проверить захват и модель**.
   Это только предпросмотр боксов: код мыши и триггера там вообще не вызывается.
5. После проверки закройте предпросмотр и нажмите **«Запустить Assist»**.
   Вернитесь в окно игры и нажмите **F8**: общий старт привязывает ввод к этому окну.

На нескольких мониторах режим захвата `auto` намеренно использует MSS: DXGI и MSS
могут по-разному нумеровать экраны. Для ручного DXGI выберите его output отдельно
(с 0), проверьте изображение в предпросмотре. Если разрешение не совпадает,
захват вернётся к MSS. Два одинаковых по разрешению экрана всё равно надо проверить
визуально. Ошибка backend видна в предупреждении, а не скрывается.

## Единое меню

Слева разделы **Обзор / Захват / Модель / Наведение / ESP / Триггер / Данные**.
Один тёмно-серый/красный стиль в стартовом и live-меню, адаптивная ширина и
прокручиваемые страницы. Настройки сохраняются в `assist_settings.json` рядом с
программой. При некорректном файле показывается предупреждение; файл можно
переименовать для сброса значений.

**Insert** в оверлее открывает live-меню. Пока оно открыто, ввод и распознавание
приостановлены; старые результаты сбрасываются. Параметры ESP/наведения/триггера
применяются без перезапуска, смена захвата/модели/provider требует F10 и нового запуска.

Горячие клавиши AI Assist (не FiveM Lab):
- **F8** — master ON/OFF; по умолчанию выключен.
- **F6** — голова/туловище; **F7** — автоматически / только ПКМ.
- **F9** — триггер ON/OFF; по умолчанию выключен.
- **F10** — аварийный выход и освобождение синтетически нажатой кнопки.
- **+ / −** основной клавиатуры — smooth; **[ / ]** — радиус захвата.

При переключении в другое окно автоматический ввод приостанавливается. Голова
и туловище в этом AI-варианте всё ещё приблизительные точки по пропорциям бокса
(0.13 / 0.42 высоты), а не игровые кости. Команды не различаются.

## Новое ядро

- **capture.py:** DXGI через DXcam, резервный MSS, явные координаты области.
  Ошибки DXGI переключают захват на MSS. При неизменном desktop DXGI может вернуть
  None: кэш используется не более 80 мс с сохранением реального времени исходного
  кадра, затем кадр обновляется MSS. В диагностике указано, чем получен текущий кадр.
- **inference.py:** независимые адаптеры PyTorch и ONNX Runtime; прогрев до старта,
  фильтр классов, проверка входной формы, letterbox/RGB/NCHW, обратное преобразование
  координат и NMS для ONNX. UI и ввод не входят в эти модули.
- **detector.py:** поток конвейера и единственный последний результат, без растущей
  очереди. Результат старого поколения после выключения/меню отбрасывается.
- **diagnostics.py:** отдельный предпросмотр без ввода и экспорт отчёта JSON.
- **tracking.py / trigger.py:** короткие треки, ограниченный прогноз, защита от
  устаревших данных, неблокирующий автомат нажатия/отпускания.

### Область захвата и дальность

`full` — выбранный монитор целиком, независимо от FOV. `center` — центральный
квадрат `crop_size`: он может помочь распознавать мелкие цели около прицела, но
**ограничивает также ESP**. В оверлее граница crop обозначена пунктиром. По умолчанию
full: переход на маленькую область не происходит тайно. DXGI сейчас получает весь
output и затем обрезает; у MSS регион ограничивает непосредственно захват.

У экранного ESP нет дальности в метрах. Распознавание зависит от размера фигуры в
пикселях и качества весов. Размер входа 960/1280 может помочь дальним целям, но
существенно замедлить CPU. Начните с 512, затем сравните профиль «Баланс» (640)
и «Быстро» (416). Низкие пороги увеличивают ложные боксы.

Сохраняются два порога: новая цель >=0.22, продолжение известной >=0.12 по умолчанию.
Пунктирный приглушённый бокс — кратковременное продолжение пропущенного трека,
не доказательство видимости за стеной. Удержание ESP по умолчанию до 350 мс от
исходного кадра; наведение — только по данным не старше 200 мс. Прогноз до 60 мс
ограничен долей размера бокса и не делает старые данные свежими. При перелётах
отключите prediction. Сглаживание бокса по умолчанию 0; smooth относится к мыши.

## ONNX и DirectML

`.pt` в режиме auto использует PyTorch. `.onnx` — наш ONNX Runtime backend.
В архиве остаётся `game_detector_final.pt` пользователя (0 player, 1 self).
Self/own_player исключается по классу, но ошибку классификации это не устраняет.
Полноценная независимая оценка этих весов не проводилась. Не загружайте недоверенные
.pt: формат может содержать исполняемую сериализацию.

1. Выберите свою .pt в разделе «Модель».
2. **Обзор → Экспорт выбранной .pt → ONNX**. Выберите путь и дождитесь результата.
   Экспорт CPU/FP32, dynamic, opset 17, без встроенного NMS/simplify. Исходные веса
   не меняются. Лог — `assist_export.log`. Закрытие меню не отменяет дочерний экспорт.
3. Полученная .onnx выбирается автоматически после успешного завершения.
4. Provider `auto` предпочитает DirectML, затем CUDA, затем CPU из установленных
   провайдеров. Явный directml/cuda при отсутствии или ошибке прогрева переходит
   на CPU с предупреждением. Список провайдеров не означает, что все узлы работают
   на GPU: ONNX Runtime может исполнять неподдержанные операции на CPU.
5. Сравните предпросмотр и задержки с .pt. ONNX/DirectML **не гарантированно быстрее**
   на вашей карте. Конвертация формата сама по себе не обучает модель лучше.

Backend рассчитан на **raw Ultralytics YOLOv8/YOLO11 detection** с metadata `names`,
одним RGB/NCHW входом batch 1, FP32/FP16 и одним выходом `[1,4+nc,N]` или транспонированным.
YOLOv5, end-to-end NMS, pose, segmentation и произвольные сторонние ONNX не угадываются:
при несовместимом формате будет понятная ошибка. Фиксированные H/W модели имеют
приоритет над размером в меню, о чём показывается предупреждение.

В одном окружении должна быть **одна** дистрибуция ONNX Runtime. Тихая установка
сохраняет уже установленный runtime; если он CPU-only, запустите
Install_Acceleration.bat вручную и подтвердите замену на DirectML. CUDA в PyTorch
и DirectML в ONNX — разные механизмы; исправлять CUDA для DirectML не требуется.
Для отдельного PyTorch CUDA-теста 1080 Ti остаётся Install_GPU_1080Ti.bat с закреплённой
старой CUDA-сборкой и реальной проверкой свёртки. На вашей Windows/GPU это требует проверки.

## Диагностика задержки

В предпросмотре и live-обзоре показаны:
- Capture — захват/копирование кадра;
- Prep — letterbox/тензор;
- Net — выполнение модели;
- Post — декодирование/NMS;
- Total — фактическое время цикла; age — возраст исходного кадра.

У PyTorch внутренние стадии берутся из Ultralytics result.speed, Total измеряется
нашими часами. У ONNX стадии измеряются непосредственно. Разница между суммой
стадий и Total включает обвязку; в предпросмотре также рисование/сжатие JPEG.
Pipeline FPS — частота завершённых обработок между результатами, не FPS игры.
P50/P95 — оценки распределения Total за последние максимум 120 обработок; окно
сбрасывается при старте/остановке. Прогрев модели в эти значения не входит.
Один и тот же кэшированный кадр DXGI повторно нейросетью не обрабатывается.

«Сохранить отчёт JSON» записывает настройки backend, стадии, предупреждение и ошибку,
но не скриншоты и не .pt. Перед передачей всё равно проверьте содержимое. Никаких
автоматических загрузок нет. Если age > aim_age, ввод прекращается и выводится STALE.
Продление боксов и повышение допустимого возраста не ускоряют сеть.

## Триггер

Выключен по умолчанию. Работает при F8 ON, в привязанном окне, вне меню, согласно
режиму auto/ПКМ (наведение мыши можно выключить отдельно). Для клика нужны последняя
подтверждённая детекция, уверенность не ниже порога новой цели, возраст <=min(120 мс,
aim_age), прицел внутри бокса и радиус допуска около выбранной точки. Далее —
непрерывная задержка и интервал кликов. Потеря цели/фокуса/меню и выход отпускают
синтетическую кнопку. Оружие, союзников и попадания модель не знает. Игры с raw input
могут игнорировать mouse_event; обхода античита и драйверных методов нет.

## Данные и обучение

В разделе «Данные» остаются сбор JPEG вокруг ЛКМ, фоновая предразметка, ручная проверка
и локальное обучение. Сбор — отдельный MSS-режим, не live-конвейер DXGI/ONNX; он
захватывает весь выбранный монитор, включая личные окна и чат. F8 — пауза/запись,
F10 — возврат к окну сбора. Максимум 500 кадров, похожие пропускаются. Данные локальны.

Предложения в suggestions/ не являются разметкой. Только явное подтверждение в
просмотре записывает annotations.json. Обучение использует проверенные кадры, минимум
30 (лучше сотни), 20 эпох, CPU по умолчанию, сохраняет кандидата отдельно в
Assist_training/<запуск>/candidate/weights/best.pt. Автозамены рабочей модели нет.
Испытайте кандидата на другой игровой сессии. Закрытие главного меню не отменяет
дочернее обучение. Передавайте веса/отчёт и примеры ошибок, не виртуальное окружение.

## Сборка Windows-приложения

Запустите основной BAT один раз, закройте Assist и запустите **Build_Assist_EXE.bat**.
Он установит PyInstaller и соберёт `Assist_app/Assist/Assist.exe`. Папку `_internal`
сохранять рядом с EXE обязательно; Python при запуске готовой сборки не требуется.
Сборка может занимать много времени и несколько ГБ из-за PyTorch. Лог — assist_build.log.
Это локальная сборка **на Windows**, не готовый EXE, полученный в Linux-среде разработки.
Альтернатива — GitHub Actions → Build Assist for Windows → Artifacts.
В EXE рабочая папка фиксируется на папке приложения; извлекайте в доступное для записи
место, не Program Files. Лог EXE — %LOCALAPPDATA%/Assist/assist.log.

## CLI и проверки

```powershell
py -m pip install -r screen_assist/requirements.txt -r screen_assist/requirements-acceleration.txt
py Assist.py --model game_detector_final.pt --capture-backend auto --capture-region full
py Assist.py --export-onnx game_detector_final.pt game_detector_final.onnx --size 512
py Assist.py --model game_detector_final.onnx --onnx-provider auto
python -m unittest discover -s . -p "test_*.py" -v
```

Проверены геометрия, настройки, ввод-автомат, RGB/letterbox, NMS, исключение self,
области захвата, fallback с заглушками и **реальная CPU ONNX-сессия на синтетической
модели**. Это не оценка качества игровых весов. Windows DXGI, DirectML/CUDA, Tk
интерфейс, PyInstaller EXE и управление игрой требуют проверки на целевом компьютере.
Новая реализация написана самостоятельно; бинарники/обфусцированный код сторонних
репозиториев не включены. Общие архитектурные идеи не отменяют лицензий чужого кода.
